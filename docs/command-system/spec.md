# Command System Spec

## 背景

XAgent 已支持少量本地斜杠命令，但这些命令由输入入口中的独立条件分支处理，缺少统一的注册、解析、帮助和补全机制。新增命令时需要直接修改界面事件逻辑，命令元数据、参数规则和执行行为无法集中管理。

当前 `/plan <内容>` 和 `/do <内容>` 只影响单次请求；界面没有持续模式状态。未识别的斜杠输入可能继续进入 Agent，导致清屏、查看状态等确定性操作产生不必要的模型调用、Token 消耗和行为不确定性。

本功能建立统一的命令注册与分发机制，让斜杠输入优先在本地解析，并根据命令类型执行本地操作、改变界面状态或向对话发送预设提示词。现有公开命令保留为隐藏兼容入口，避免已有使用方式回退。

## 目标

- 集中管理命令名称、别名、说明、用法、类型、参数提示、可见性和执行行为。
- 在启动阶段发现名称或别名冲突，并立即终止启动。
- 让斜杠命令绕过普通 Agent 输入路径，获得快速、确定且节省 Token 的响应。
- 支持本地命令、界面状态命令和预设提示词命令三种执行模式。
- 通过抽象界面控制能力，使命令实现不依赖具体终端渲染框架。
- 支持大小写不敏感的解析、别名、帮助信息和 Tab 命令补全。
- 提供十个高频内置命令，并保持现有命令的隐藏兼容入口。
- 让计划模式在当前会话内持续生效，并在状态栏中明确展示 `[DEFAULT]` 或 `[PLAN]`。

## 功能需求

- F1：系统必须提供统一命令注册中心，集中保存命令名称、别名、简短描述、用法示例、命令类型、可选参数提示、隐藏标记和执行行为。
- F2：系统必须在启动阶段以大小写不敏感方式检查全部命令名称和别名。任何名称—名称、名称—别名或别名—别名冲突都必须立即导致启动失败，不得延迟到运行时处理。
- F3：输入解析必须先去除首尾空白；空输入直接返回。只有首个非空字符为 `/` 的输入才进入命令分发，命令名与后续参数以第一个空白边界分隔。
- F4：命令名称和别名必须大小写不敏感，参数内容保持原始大小写和内部空格，不得被无意改写。
- F5：已识别的斜杠命令必须绕过普通 Agent 输入路径。未识别的斜杠命令也不得发送给模型，而是在本地显示未知命令错误，并引导用户使用 `/help`。
- F6：不以 `/` 开头的非空输入必须保持现有行为，作为普通用户消息发送给 Agent。
- F7：命令必须分为三种执行类型：
  - 本地命令：读取或处理本地状态并立即显示结果。
  - 界面状态命令：改变当前界面或会话模式。
  - 提示词命令：展开预设提示词，并通过正常对话路径交给 Agent。
- F8：命令执行只能依赖一组抽象界面能力，包括显示消息、发送用户消息、切换模式、读取 Token 使用情况和刷新状态；命令行为不得直接依赖具体终端渲染框架。
- F9：系统必须支持命令名和别名的 Tab 补全。只有一个可见匹配项时直接补全为规范命令名；存在多个可见匹配项时显示可选择的候选菜单；隐藏命令不得出现在补全结果中。
- F10：首版 Tab 补全只处理命令名和别名，不补全参数值。参数提示可以显示在候选菜单和帮助信息中。
- F11：`/help`（别名 `/h`、`/?`）必须列出全部非隐藏命令的名称、别名、简短描述、用法和参数提示；不得展示隐藏兼容入口。
- F12：系统必须提供以下本地命令：
  - `/compact`（别名 `/ctx`）：立即压缩当前会话上下文，并显示实际压缩结果；没有活动会话时给出本地提示。
  - `/session`（别名 `/sess`）：显示当前会话 ID、消息数量、当前模式和流式响应状态。
  - `/memory`（别名 `/mem`）：显示用户级与项目级记忆的启用状态、条目数量和诊断摘要。
  - `/permission`（别名 `/perm`）：只读显示当前权限模式、各层规则数量和加载错误，不修改权限配置。
  - `/status`（别名 `/st`）：显示 Provider、模型、当前模式、本次请求 Token 与缓存统计、流式状态、MCP 状态和最近错误。
- F13：系统必须提供以下界面状态命令：
  - `/clear`（别名 `/cls`）：只清空当前消息显示，不删除会话历史，不改变 Agent 上下文。
  - `/plan`（别名 `/p`）：把当前会话切换到计划模式；后续普通消息持续使用计划模式。
  - `/do`（别名 `/d`）：退出计划模式，恢复默认执行模式。
- F14：计划模式必须在当前会话内持续，直到执行 `/do`。新建会话、打开其他会话或重新启动应用时必须恢复默认模式，不持久化此前模式状态。
- F15：状态栏必须始终显示当前模式。默认执行状态显示 `[DEFAULT]`，计划状态显示 `[PLAN]`。模式切换后状态栏必须立即刷新。
- F16：计划模式下发送的所有普通请求都必须继续受现有只读工具限制保护；退出计划模式后恢复默认执行能力。
- F17：`/review`（别名 `/rv`）必须展开固定审查提示词，要求 Agent 审查当前工作区未提交改动，优先报告正确性、安全性、回归风险和测试缺口，不主动修改代码。展开后的完整提示词必须作为用户消息显示并保存到会话历史。
- F18：系统必须保留现有 `/permissions status`、`/mcp status`、`/diagnostics` 和 `/memory status|index|off|delete|rebuild` 行为，作为隐藏兼容入口；它们不得出现在 `/help` 或 Tab 补全中。
- F19：命令处理结果、错误和提示中可能包含的路径、诊断或状态内容必须继续经过现有敏感信息脱敏处理。
- F20：单匹配补全、多匹配候选选择、命令执行或命令错误都不得触发模型请求；只有提示词命令展开后以及普通非命令输入才可以进入 Agent。

## 非功能需求

- N1：命令识别、别名解析、帮助生成和补全匹配必须是确定性的；相同注册内容和输入必须产生相同结果。
- N2：注册中心输出顺序必须稳定。帮助列表和补全候选不得因非确定性遍历而随机变化。
- N3：命令解析、帮助、补全、清屏、模式切换及只读状态查询不得调用模型或消耗对话 Token。`/review` 只有在展开提示词并进入正常对话后才允许调用模型。
- N4：命令分发层必须能够脱离具体 TUI 独立测试；注册、解析和补全测试不得要求启动真实终端或连接 Provider。
- N5：新增机制不得改变普通非命令输入、会话保存、流式响应、权限确认、上下文压缩和 Plan Mode 只读保护的既有行为。
- N6：隐藏兼容命令必须保持现有语义，但不得污染新的公开命令帮助和补全体验。
- N7：所有命令输出必须沿用项目现有脱敏边界，不得通过状态、诊断、会话或记忆摘要泄露 API Key、Token、密码等敏感信息。
- N8：模式状态、消息显示和状态栏必须保持一致；一次模式切换完成后，后续输入分流和界面标记不得观察到不同模式。
- N9：Tab 补全必须保持交互响应，不得执行文件扫描、网络请求、模型请求或其他阻塞型工作。
- N10：命令冲突必须在应用可接受用户输入前暴露，并提供足以定位冲突名称及参与命令的信息。
- N11：新增实现必须符合现有 Go 项目的格式化、静态检查和测试要求，并在现有支持 ANSI 的终端环境中工作。
- N12：首版命令与模式状态无需持久化；重启、创建会话或切换会话时的默认行为必须稳定且可预测。

## 不做的事

- 不支持用户通过配置文件、项目文件或运行时 API 注册自定义命令。
- 不从 Skill、MCP 或插件动态发现和注册命令。
- 不根据当前项目、会话内容或模型输出动态生成提示词命令。
- 不实现命令级权限声明、授权规则或独立确认流程；命令触发的既有操作仍遵守原有安全边界。
- 不实现参数值、文件路径、会话 ID 或记忆条目的 Tab 补全。
- 不为 `/session` 增加新建、列表、切换、重命名或删除会话能力。
- 不让 `/permission` 修改当前或持久化权限模式。
- 不让 `/clear` 删除会话历史、重置 Agent 上下文或创建新会话。
- 不持久化 `[DEFAULT]`/`[PLAN]` 模式，也不在会话之间继承模式。
- 不让 `/review` 自动修复发现的问题。
- 不移除或改变现有隐藏兼容命令的行为。
- 不在本阶段建设通用命令脚本系统、命令市场或 Skill 命令桥接层。

## 验收标准

- AC1（覆盖 F1、F7）：注册十个内置命令后，系统能够读取每条命令的名称、别名、描述、用法、类型、参数提示、隐藏状态和执行行为，并能区分本地、界面状态、提示词三类命令。
- AC2（覆盖 F2）：分别制造名称—名称、名称—别名、别名—别名及大小写不同但规范化后相同的冲突，应用均在接受用户输入前立即失败，并指出冲突名称及相关命令。
- AC3（覆盖 F3、F4）：输入空字符串或纯空白时不执行任何操作；输入带首尾空白和混合大小写的命令时能够命中；命令后的参数保留原始大小写和内部空格。
- AC4（覆盖 F5）：输入不存在的 `/unknown` 时，本地显示未知命令及 `/help` 引导，不产生用户对话消息，也不发生 Provider 请求。
- AC5（覆盖 F6）：输入不以 `/` 开头的普通文本时，仍按现有路径发送给 Agent，并正常进入流式响应。
- AC6（覆盖 F8）：使用不依赖真实终端的替代界面控制器，可以独立执行命令并观察显示消息、发送用户消息、切换模式、读取 Token 和刷新状态等调用。
- AC7（覆盖 F9、F10）：输入唯一命令前缀后按 Tab，输入框直接补全为规范命令名；补全过程不尝试补全参数。
- AC8（覆盖 F9、F10）：输入存在多个匹配项的前缀后按 Tab，出现稳定排序的候选菜单，并能选择一个候选完成输入。
- AC9（覆盖 F9、F18）：隐藏兼容命令不会出现在单匹配、多匹配候选或候选菜单中。
- AC10（覆盖 F11）：执行 `/help`、`/h` 或 `/?` 时，均显示十个公开命令的名称、别名、描述、用法和参数提示，且不显示隐藏兼容入口。
- AC11（覆盖 F12）：在有活动会话时执行 `/compact` 或 `/ctx`，上下文压缩立即开始并显示实际结果；没有活动会话时只显示本地提示。
- AC12（覆盖 F12）：执行 `/session` 或 `/sess`，显示与当前状态一致的会话 ID、消息数量、模式和流式状态，不触发 Provider 请求。
- AC13（覆盖 F12）：执行 `/memory` 或 `/mem`，显示用户级和项目级记忆的启用状态、条目数量及脱敏后的诊断摘要。
- AC14（覆盖 F12）：执行 `/permission` 或 `/perm`，显示权限模式、各层规则数量和加载错误；执行前后权限配置保持不变。
- AC15（覆盖 F12）：执行 `/status` 或 `/st`，显示当前 Provider、模型、模式、请求 Token、缓存统计、流式状态、MCP 状态和最近错误，且各项与实际运行状态一致。
- AC16（覆盖 F13）：执行 `/clear` 或 `/cls` 后，当前消息区域为空；会话历史消息数量和 Agent 上下文保持不变，重新加载该会话仍能看到原历史。
- AC17（覆盖 F13、F14、F15）：执行 `/plan` 或 `/p` 后，状态栏立即显示 `[PLAN]`；连续发送多条普通消息时均使用计划模式，直到执行 `/do`。
- AC18（覆盖 F13、F14、F15）：执行 `/do` 或 `/d` 后，状态栏立即恢复 `[DEFAULT]`，后续普通消息使用默认执行模式。
- AC19（覆盖 F14）：进入计划模式后，新建会话、打开其他会话或重启应用，状态均恢复 `[DEFAULT]`。
- AC20（覆盖 F16）：计划模式下连续多轮请求均只暴露或执行只读工具；模型尝试写文件或执行非只读操作时继续被现有保护拒绝。
- AC21（覆盖 F17）：执行 `/review` 或 `/rv` 后，界面显示并在会话历史保存完整展开的审查提示词；Agent 收到该提示后只审查当前未提交改动，优先报告正确性、安全性、回归和测试问题，不主动修改文件。
- AC22（覆盖 F18）：现有 `/permissions status`、`/mcp status`、`/diagnostics` 和全部 `/memory` 兼容子命令仍产生与改造前一致的本地行为，同时不出现在公开帮助与补全中。
- AC23（覆盖 F19）：让诊断、路径、记忆或状态中包含模拟 Token、API Key 和密码，所有公开及隐藏命令输出均不出现原始敏感值。
- AC24（覆盖 F20）：执行帮助、补全、清屏、模式切换、会话/记忆/权限/状态查询、未知命令和隐藏兼容命令时，Provider 请求计数保持不变；只有 `/review` 展开后或普通输入会进入 Agent。
- AC25（覆盖 F1–F20）：运行项目全部自动化测试、静态检查和格式检查均通过，现有会话、Agent Loop、权限、记忆、上下文和 TUI 行为没有回归。
