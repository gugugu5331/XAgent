# 子 Agent Worktree 隔离 Spec

> 实现状态：T1–T69 自动化实现与质量门禁已完成（2026-08-16）；人工 tmux 场景 AC51/E1–E3 待执行。证据见 [verification.md](./verification.md)。

## 背景

XAgent 已具备子 Agent 的角色定义、任务委派、前后台执行、运行时状态隔离、权限收窄、工具过滤、结果回流和任务生命周期管理。当前子 Agent 虽然拥有独立的消息、授权、文件读取缓存和用量状态，但仍与主 Agent 使用同一个项目工作目录。

当主 Agent 与一个或多个子 Agent 并行修改同一 Git 仓库时，共享工作目录会产生以下问题：

1. 不同 Agent 对同一文件的并发修改可能互相覆盖，工具读取到的内容也可能在任务执行期间被其他 Agent 改变。
2. 主 Agent 的未提交修改会直接影响子 Agent，子 Agent 的中间文件和构建产物也会反向干扰主 Agent。
3. 仅隔离消息和缓存不能形成完整的文件系统边界；工具、项目指令、hooks、运行配置和路径相关缓存仍可能绑定到主项目目录。
4. 子 Agent 完成后，缺少统一的变更保护和目录回收机制，无法安全判断临时工作目录应当删除还是保留。
5. 由模型生成的目录名称和生命周期操作可能引入路径遍历、目录冒充或误删仓库外文件等安全风险。

本功能为明确声明需要 Worktree 隔离的子 Agent 任务创建独立 Git 工作目录。每个任务从委派瞬间的当前 `HEAD` commit 开始，在独立临时分支中运行，不继承主工作目录的未提交修改。子 Agent 的所有路径相关操作都绑定到其绝对工作目录，不通过切换进程工作目录实现隔离。

Worktree 完成后的代码合并仍由上层通过标准 Git 流程决定；本功能只负责安全地创建、使用、保留和清理隔离工作目录。

## 目标

- 为每个声明 Worktree 隔离的子 Agent 任务创建唯一、独立的 Git 工作目录和本地临时分支，使主 Agent 与多个子 Agent 可以并行修改同一仓库而不互相覆盖。
- 让每个隔离任务固定基于创建时的当前 `HEAD` commit；主工作目录的未提交修改和创建后的文件变化均不自动进入子 Agent 工作目录。
- 提供创建、只读快速恢复、进入、退出、删除和后台过期清理的完整生命周期。
- 使用严格的名称、路径、仓库身份和受控元数据校验，阻止路径遍历、目录冒充、越界操作和错误删除。
- 在创建后按项目显式白名单完成环境初始化，包括复制本地配置、设置 Worktree 专属 Git hooks、软链大型依赖目录，以及补齐被 Git 忽略但运行必需的文件。
- 将绝对工作目录作为任务运行上下文显式传递给所有路径相关工具和组件；文件内容、项目指令、系统提示词和项目记忆等路径相关缓存按绝对路径或等价的根目录身份隔离。
- 只向隔离任务开放能够证明支持任务级工作目录或明确与目录无关的工具，避免工具绕回主项目目录。
- 通过角色定义中的隔离声明自动启用 Worktree；未声明隔离的子 Agent 保持现有行为。
- 在任务退出和后台清理时保护未提交修改与未推送 commit；仅在确认成果不会丢失时删除 Worktree 目录和本地临时分支，永不自动删除远端分支。
- 保持 Worktree 的创建与回收独立于代码合并、跨目录同步和多 Agent 编排策略。

## 功能需求

### 隔离声明与工作区身份

- **F1：** 角色定义允许使用 `isolation: worktree` 声明隔离。当前版本唯一合法的显式值为 `worktree`；字段省略时保持现有共享项目目录行为。显式空值、其他字符串、非字符串或其他格式均使该角色定义无效，并产生脱敏诊断。
- **F2：** Defined 子 Agent 使用其角色声明的隔离模式；Fork 子 Agent 仅在附带声明了 Worktree 隔离的角色时启用隔离。委派请求不能临时关闭、放宽或覆盖角色要求的隔离模式。
- **F3：** 每个启用 Worktree 隔离的子 Agent 任务必须独占一个工作目录和一个本地临时分支。不同任务即使使用相同角色，也不得复用同一工作区。
- **F4：** 每个受管工作区必须拥有持久、不可混淆的工作区身份。任务执行 ID 可以继续用于进程内调度，但不得单独作为跨进程恢复、资源归属和删除授权的依据。
- **F5：** 工作区身份必须在任务准备阶段确定，并在任务生命周期内保持不变。显示名称、角色名称、任务正文和其他模型生成内容不得直接作为未经校验的目录或分支名称。
- **F6：** 快速恢复只恢复工作区资源和生命周期状态，不恢复已经中断的子 Agent 模型执行、消息循环或后台任务。应用重启后不得把中断任务伪装为继续运行或正常完成。

### 受控根目录与名称安全

- **F7：** 所有受管 Worktree 必须位于 XAgent 启动时主项目工作目录内部的专用受控根目录下。该根目录绑定主仓库身份，不能相对于子 Worktree 再次派生。
- **F8：** 受控根目录及其内容不得被 Git 跟踪，并且创建、使用和清理 Worktree 不得使主工作目录新增未跟踪路径。系统不得为满足该条件自动修改或提交项目文件；无法证明受控根被精确忽略时，创建失败。
- **F9：** 忽略范围必须只覆盖 Worktree 管理目录，不得顺带隐藏角色、Skill、权限、本地配置或其他项目文件。
- **F10：** 用于目录和临时分支映射的逻辑名称必须经过统一规范化。名称由斜杠分隔的安全段组成；每段只允许小写 ASCII 字母、数字、点、下划线和连字符，并且必须以字母或数字开头和结尾。
- **F11：** 名称必须拒绝空段、`.`、`..`、`.git`、管理保留段、以 `.lock` 结尾的段、连续斜杠、反斜杠、绝对路径、驱动器前缀、控制字符、NUL、前后空白和任何规范化后发生语义变化的输入。
- **F12：** 名称总长度不得超过 192 字节，单段不得超过 64 字节，嵌套深度不得超过 8 层。超限输入必须在执行文件系统或 Git 修改前被拒绝。
- **F13：** 资源身份比较必须遵循目标文件系统的实际路径等价规则。在大小写不敏感的文件系统上，大小写不同但等价的名称必须视为冲突。
- **F14：** 临时分支名称必须位于固定管理命名空间中，并由工作区身份确定性生成。名称中必须包含足够的抗碰撞身份信息，不得只依赖可能重复的人类可读名称。
- **F15：** 目标路径必须通过规范化绝对路径、受控根身份和逐层对象检查证明位于受控根内。仅靠字符串前缀或一次性的真实路径解析不足以授权创建、恢复或删除。
- **F16：** 受控根至目标目录之间的已有路径组件不得是符号链接或特殊文件。所有修改和删除操作必须以已验证的受控根为锚点，逐段执行不跟随符号链接的相对操作，并在实际操作前重新确认对象身份。
- **F17：** 路径安全检查与后续使用之间必须受到同一生命周期锁保护，防止检查完成后目录被替换。目标平台无法提供等价的竞态保护时必须失败关闭，不得退化为普通路径字符串操作。

### 创建、持久状态与并发控制

- **F18：** 创建前必须确认当前目录属于可用的 Git 仓库、`HEAD` 可解析为 commit、受控根安全且目标身份未被其他工作区占用。unborn `HEAD`、非 commit 对象或身份冲突均使创建失败。
- **F19：** 系统必须在仓库级创建锁内将委派时的 `HEAD` 一次解析为不可变 commit ID。后续临时分支和 Worktree 始终从该 commit ID 创建，不得重新解析可能已经变化的符号 `HEAD`。
- **F20：** 主工作目录中的暂存修改、未暂存修改和未跟踪文件不得进入子 Worktree。主工作目录处于 dirty 状态本身不阻止创建。
- **F21：** 生命周期必须先在子 Agent 无权写入的管理域中登记创建意图，再执行 Git 和文件系统操作，最后原子发布可用状态。权威记录至少包含工作区身份、仓库身份、规范化目录、临时分支、基准 commit、初始化摘要、生命周期状态和关键时间。
- **F22：** Worktree 内的标记只能用于交叉校验，不能单独授权恢复、进入或删除。权威元数据、锁和租约必须存放在子 Agent 项目写入边界之外。
- **F23：** 生命周期必须能区分至少以下状态：创建中、初始化中、可进入、活跃、结算中、因变更保留、删除中、已删除、部分完成和需要人工处理。
- **F24：** 创建、初始化、进入、结算和删除操作必须具有可恢复的一致性。进程在任一步骤中断后，下一次启动必须能把资源识别为可安全继续、可安全回滚、已部分完成或需要人工处理；不得将不确定状态自动视为成功。
- **F25：** 同一工作区的生命周期操作必须互斥。同一仓库内会修改 Git 公共状态、临时分支命名空间或权威元数据的步骤还必须受到仓库级跨进程排他控制。
- **F26：** 锁顺序必须固定；竞争、超时或锁持有者状态不确定时失败关闭。重复请求只能得到同一资源的幂等结果或明确冲突，不得创建多个目录、多个临时分支或相互删除资源。

### 只读快速恢复

- **F27：** 当目标目录已存在时，系统进入快速恢复路径。该路径只允许读取文件系统和执行明确无副作用的只读 Git 检查。
- **F28：** 快速恢复不得执行 Worktree 创建、注册、修复、移动、删除、prune、分支创建、引用修改、配置修改、环境初始化或其他会改变仓库与文件系统状态的 Git 操作。
- **F29：** 快速恢复必须交叉验证权威元数据、工作区身份、仓库公共目录身份、规范化路径、Worktree 注册、临时分支、当前 HEAD、基准 commit 和 Git 管理文件指向。
- **F30：** 快速恢复只接受由 XAgent 创建且身份完全匹配的工作区。元数据缺失或损坏、目录被替换、Git 注册缺失、分支被移动、管理文件指向异常或任何状态无法确定时，必须拒绝恢复。
- **F31：** 快速恢复不得自动接管手工创建的 Worktree，不得修复不一致状态，也不得重新执行环境初始化。
- **F32：** 快速恢复必须通过只读检查验证初始化清单中的目标路径、类型和内容指纹仍符合创建完成时的记录。缺失、不一致或无法验证时，恢复失败并保留现场。

### 环境初始化

- **F33：** 新建 Worktree 后、子 Agent 进入前，系统必须根据项目级显式白名单完成环境初始化。未声明的本地文件、忽略文件和依赖目录一律不复制、不链接。
- **F34：** 初始化规则必须区分：复制本地配置、设置 Worktree 专属 Git hooks、软链只读共享依赖，以及补齐被 Git 忽略但运行必需的文件。每条规则必须明确源、目标和操作类型。
- **F35：** 初始化规则中的源和目标必须使用受限相对路径；目标解析后必须位于子 Worktree 内。规则不得通过路径遍历、符号链接父目录或竞态替换把写入导向 Worktree 之外。
- **F36：** 复制规则默认只允许读取普通文件和真实目录，不跟随源目录内的符号链接，并拒绝设备文件、FIFO、Socket 及其他特殊对象。复制过程必须限制单文件大小、总大小、文件数和递归深度。
- **F37：** 复制目标必须使用安全的新建或受控替换语义，不得覆盖初始化器无法证明归属的既有对象；复制后的文件不得保留 setuid、setgid 等特殊权限位。
- **F38：** 软链规则只能指向显式允许、可视为只读且能够被多个任务安全共享的依赖目录。软链目标不得指向主工作目录、其他 Worktree、Git 管理目录或受控 Worktree 根目录。
- **F39：** 声明为只读的共享依赖不得被任务修改。需要写入的依赖、缓存或构建目录必须复制到任务私有位置或为任务单独创建；若运行环境无法阻止经软链写入，则不得创建该共享软链。
- **F40：** 系统不得扫描、猜测或自动复制 `.env`、凭据、用户目录内容及其他常见敏感文件。白名单授权只允许复制指定对象，不允许扩大为目录外的隐式发现。
- **F41：** Git hooks 必须使用经验证的 Worktree 级配置，不得通过仓库级共享配置改变主工作目录或其他 Worktree 的 hooks 行为。需要启用仓库级 Worktree 配置能力时，必须作为显式、幂等且可回滚的仓库准备步骤。
- **F42：** 初始化开始前必须记录本次事务的预期产物清单及不含敏感内容的完整性摘要。初始化创建的复制文件、软链和忽略文件必须能与该清单逐项核对。
- **F43：** 初始化采用整体成功语义。任一步骤失败时，子 Agent 不得启动；仅当工作区尚未进入使用，且全部现存变化都能证明由本次初始化事务产生并保持原样时，才允许受控回滚目录和本地临时分支。
- **F44：** 初始化失败时发现无法归因的文件、内容变化、身份变化或并发访问，必须按用户成果保护并保留现场，不得强制删除。
- **F45：** 初始化日志、事件和诊断不得暴露文件内容、敏感环境变量、凭据或白名单源的本机私有路径。受管 Worktree 的绝对路径只允许在当前任务私有运行时中使用。

### 任务级工作区运行时

- **F46：** Worktree 创建或恢复并完成校验后，系统才允许子 Agent 进入。进入操作必须建立不可变的任务工作区上下文和具有持有者身份、心跳及失效语义的活跃租约。
- **F47：** 活跃租约期间，其他进程和后台清理器不得删除或接管该工作区。仅凭 PID、时间戳或本进程任务表不足以判断工作区不活跃。
- **F48：** 系统不得通过进程级 `chdir` 切换目录。任务工作区的规范化绝对路径必须作为显式运行上下文传递给所有项目路径相关操作。
- **F49：** 进入 Worktree 时必须派生任务级项目安全根、项目写入能力、工具执行绑定、命令默认工作目录、读取范围、临时目录和工具能力视图。仍持有主工作区根、主工作区写入能力或固定主项目路径的执行对象不得被隔离任务复用。
- **F50：** 所有项目相对路径解析、项目源码读取和项目源码写入必须绑定任务 Worktree。项目写入不得落到主工作目录或其他 Worktree。
- **F51：** 项目工作区隔离允许访问系统工具链、Git 公共元数据、任务私有临时目录、用户级只读配置和显式声明的只读共享依赖；这些例外不得被解释为对主工作目录或其他 Worktree 的写权限。
- **F52：** 本功能用于防止正常 Agent 工具之间的项目文件覆盖，不构成针对同用户权限恶意进程的操作系统级安全沙箱。即使如此，无法施加项目写入边界的命令、Hook、MCP 或第三方工具仍不得向隔离任务开放。
- **F53：** 文件读取、写入、编辑、搜索和其他路径相关工具必须在解析符号链接后执行访问边界校验，并继续受既有权限、Plan Mode、Hook 和命令安全策略约束。
- **F54：** 命令执行除接收任务级工作目录外，还必须使用现有或等价的进程保护机制约束项目写入范围。无法保证项目写入只落入任务 Worktree 和任务私有区域时，该命令工具必须被过滤。
- **F55：** XAgent runtime hooks 与 Git hooks 必须分别处理。隔离任务的 runtime hook 事件、命令工作目录、项目根字段、环境和项目 hook 配置来源必须绑定任务 Worktree；无法任务化的文件系统相关 hook action 必须禁用。
- **F56：** 工具必须通过本地可信能力元数据声明为“与工作区无关”“消费任务工作区上下文”“固定绑定某个工作区”或“未知”。远端工具描述和模型输出只能收窄能力，不能把未知工具提升为安全能力。
- **F57：** Worktree 子 Agent 只能使用经过适配和测试、能够实际消费任务工作区并遵守访问边界的工具，或经本地配置证明与工作区无关的工具。仅由工具自行声明支持 `cwd` 不足以获得访问资格。
- **F58：** 固定绑定主工作区和能力未知的工具必须从 Worktree 子 Agent 的工具集合中移除。被过滤工具不得出现在发送给模型的工具定义中，伪造调用必须被拒绝且不得执行。
- **F59：** MCP 和插件工具遵守相同规则。进程启动时绑定主工作区的本地服务不能被隔离任务复用；远程服务也必须由本地可信配置声明为工作区无关，不能只信任远端自述。

### Prompt、项目指令、Memory 与缓存隔离

- **F60：** Defined 隔离任务必须从 Worktree 重新加载项目指令、项目级稳定上下文和项目记忆；不得使用启动时绑定主工作目录的单例项目上下文。
- **F61：** Fork 隔离任务保留父会话消息和与项目目录无关的稳定上下文，但必须移除或替换父 Prompt 中绑定主工作目录的项目指令、项目记忆、项目根和路径说明，再从 Worktree 加载对应内容。
- **F62：** 角色定义和角色正文继续使用委派准备时冻结的已解析快照，不因进入 Worktree 而重新发现或替换角色。
- **F63：** 注入给子 Agent 的任务私有路径说明必须明确当前绝对工作目录、基准 commit、本地临时分支、允许的外部只读区域，以及禁止写入主工作目录和其他 Worktree 的边界。
- **F64：** 文件内容、系统提示词、项目指令、项目记忆和其他依赖项目路径的缓存必须按规范化绝对路径或等价的不可伪造根目录身份区分。不同 Worktree 不得命中主工作目录或其他 Worktree 的路径相关缓存。
- **F65：** 工作目录切换不得触发全局缓存清空。目录隔离必须通过任务运行时和缓存键自然实现，不得清除或污染主 Agent 与其他任务的缓存。
- **F66：** 当前任务私有 Prompt 可以使用经校验的绝对 Worktree 路径；持久日志、遥测、跨任务事件、任务列表和上层结果默认只展示稳定工作区标识或仓库内相对显示位置。

### 结算、变更保护与删除

- **F67：** 从 Worktree 创建成功开始，到任务正式注册、排队、运行和结算结束，必须由同一个资源所有权边界负责工作区。任务准备成功后发生参数校验失败、准入失败、队列失败或事件发布失败时，也必须进入结算。
- **F68：** 每个已创建工作区的任务必须拥有一次性、幂等的结算能力。正常完成、失败、取消、超时、达到轮次上限、排队移除和应用关闭都必须触发结算。
- **F69：** 子 Agent 达到停止条件后，系统必须先停止或确认不存在仍可能访问 Worktree 的任务进程、runtime hook 和子进程，再释放活跃租约并检查变更。
- **F70：** 工作区结算完成前不得发布任务最终结果。结算超时、检查失败或状态不确定时必须保留工作区，并把“结算未完成”或相应保留原因作为可观测结果。
- **F71：** 结算不得隐式合并、变基、提交、推送、设置上游、拉取远端状态或同步代码。
- **F72：** 受保护文件变化必须覆盖暂存修改、未暂存修改、冲突、intent-to-add、未跟踪文件、子模块或嵌套仓库变化，以及未被初始化清单覆盖的 ignored 文件。
- **F73：** 初始化清单中的复制文件、软链和 ignored 文件，只有在路径、类型和内容指纹仍与初始化完成时一致时，才能视为可丢弃。发生变化或出现额外 ignored 文件时，必须视为未提交成果。
- **F74：** 只有配置为有效远端跟踪引用的 upstream 才能作为已推送证明，并且临时分支当前 tip 必须可达于该本地可见的远端跟踪引用。
- **F75：** 系统不得为判断是否已推送而自动执行 fetch、push、设置 upstream 或访问网络。无 upstream、upstream 为本地分支、远端跟踪引用缺失、分支 tip 不可达或检查失败时，只要分支相对基准产生了 commit，就视为存在未推送 commit。
- **F76：** 存在受保护文件变化或未推送 commit 时，默认拒绝删除 Worktree 和本地临时分支，并把工作区标记为“因变更保留”。任务执行状态仍按实际结果结束。
- **F77：** 仅当工作区无受保护文件变化、分支无未推送 commit、临时分支未被其他 Worktree 使用且所有身份校验通过时，才允许自动删除。
- **F78：** 安全删除同时移除 Worktree 目录和精确匹配的本地临时分支，但永不删除远端分支。当前版本不提供绕过变更保护的自动强制删除。
- **F79：** 删除必须再次验证受控根、权威元数据、仓库身份、Worktree 注册、分支身份、活跃租约和变更保护，并在取得排他删除租约后执行。
- **F80：** 任一验证失败均停止删除，不得降级为普通递归目录删除。Worktree 已移除但分支删除失败等部分完成情况必须持久记录，并在后续安全检查中继续结算或报告人工处理。
- **F81：** 任务最终结果必须包含：是否启用隔离、稳定工作区标识、基准 commit、本地临时分支、结算状态、是否已清理、是否因变更保留及保留原因。默认不得包含本机绝对路径。

### 后台过期清理

- **F82：** 系统必须在启动后和运行期间定期扫描受管工作区。默认在任务首次进入终态后的 24 小时判定过期；重复扫描、只读检查和检查失败不得刷新该时间。
- **F83：** 尚未记录终态但活跃租约已经失效的中断资源，按最后一次有效租约时间计算过期；过期配置必须具有安全的最小值和最大值。
- **F84：** 后台清理必须经过三层过滤：
  1. 路径层：候选位于规范化受控根内，目录名称、路径对象和真实身份安全；
  2. 归属层：候选具有完整权威元数据，工作区、仓库、Worktree、分支和生命周期身份一致；
  3. Git 与变更保护层：清理器已取得排他删除租约，工作区不活跃、无受保护文件变化、无未推送 commit。
- **F85：** 任一过滤层失败、锁竞争、检查超时、Git 状态不确定或目录正在使用时，清理器必须跳过候选。过期不得突破未提交修改和未推送 commit 保护。
- **F86：** 清理器不得跟随受控根内的符号链接扫描外部目录，不得接管无权威元数据目录，也不得删除手工 Worktree、主工作目录、其他仓库或身份未知的资源。
- **F87：** 对于身份已验证的受管 Worktree，只有初始化清单中可证明未改变的临时产物可以随安全删除一并移除；未知文件或内容变化必须保留整个工作区。
- **F88：** 后台清理必须具有可配置且有上限的单轮候选数、总执行时长和并发数。达到任一预算后停止本轮，将剩余候选留到后续扫描。
- **F89：** 清理器不得长期持有会阻塞 Agent 工具执行的全局锁；与前台生命周期操作竞争时，优先跳过并等待后续扫描。
- **F90：** 清理结果必须产生有界、脱敏的可观测记录，包括已删除、因活跃跳过、因变更保留、身份不匹配、部分完成和检查失败的数量，不得输出文件内容、凭据或非受管本机绝对路径。

## 非功能需求

### 安全性

- **N1：安全失败。** 路径、仓库身份、Git 状态、元数据、锁、租约、工具能力或变更保护存在歧义时，系统必须拒绝创建、进入或删除，不得通过猜测、自动修复或降低校验强度继续执行。
- **N2：最小权限。** Worktree 子 Agent 只能获得完成任务所需的项目工作区能力。主工作目录、其他 Worktree、受控管理域和未声明外部路径不得因为启用隔离而变得可写。
- **N3：不可自证。** 子 Agent 可写区域中的文件、标记、工具输出和模型文本不能单独作为资源归属、工具安全能力、已推送状态或删除授权的证据。
- **N4：防竞态。** 所有安全敏感的文件系统检查必须与后续操作绑定在同一受保护窗口内；不得长期复用可能已因路径替换、分支移动或外部 Git 操作而失效的检查结果。
- **N5：无自动成果丢失。** 没有完整正向证据证明工作区可安全删除时，系统必须保留工作区和本地临时分支。磁盘占用、过期时间和应用关闭均不得降低该保护。
- **N6：命令参数安全。** 所有传给 Git、Hook、子进程和第三方工具的路径、分支、引用及配置值必须作为结构化参数传递，不得拼接为可被 Shell 二次解释的命令文本。
- **N7：资源限制。** 名称、配置规则、复制文件、目录深度、元数据、诊断、锁等待、Git 输出和清理候选都必须具有默认上限与硬上限，防止恶意配置或异常仓库造成无界 CPU、内存、磁盘和句柄消耗。
- **N8：信任边界明确。** 本功能保证正常 XAgent 工具的项目工作区隔离，不承诺抵御同一操作系统用户权限下专门设计的恶意进程。该边界必须在用户文档和诊断中保持一致，不能把显式 `cwd` 描述成操作系统级沙箱。

### 数据保护与隐私

- **N9：敏感内容最小暴露。** 初始化文件内容、凭据、环境变量、远端认证信息、用户目录、Git 配置秘密和非受管绝对路径不得进入普通日志、遥测、跨任务事件或任务最终结果。
- **N10：路径分级展示。** 经校验的绝对 Worktree 路径只允许用于当前任务的本地私有运行上下文；用户界面、持久记录和上层结果默认展示稳定工作区标识或仓库内相对位置。
- **N11：元数据无秘密。** 权威生命周期元数据和初始化清单只能保存身份、状态、相对路径、文件类型、大小、时间和不可逆完整性摘要，不得保存初始化文件原文、凭据或可恢复的敏感配置值。
- **N12：权限保守。** 新建管理目录、元数据、锁和任务私有文件必须使用仅当前用户可访问的权限；复制文件不得扩大源文件权限，不得保留特殊执行权限位。
- **N13：脱敏一致。** Worktree 创建、恢复、Git 错误、初始化失败、工具过滤、结算和后台清理必须复用现有脱敏边界，并对错误内容和路径长度做限制。

### 一致性与可靠性

- **N14：事务可恢复。** 生命周期状态更新必须采用原子发布方式。进程崩溃、系统断电或写入中断后，不得把部分写入的元数据当作有效状态。
- **N15：幂等性。** 对同一工作区重复执行创建、恢复、进入、退出、结算和删除，不得产生重复分支、重复 Worktree、重复初始化、重复终态或越过变更保护。
- **N16：单一终态。** 子 Agent 的执行结果、工作区结算结果和对外任务终态必须形成一次性一致快照。终态发布后不得因迟到的 Runner、Hook 或清理事件静默改写为另一状态。
- **N17：部分失败可见。** Git 资源、目录、分支和权威元数据出现部分完成时，系统必须保留可恢复状态和明确诊断，不得用模糊的成功或普通失败隐藏残留资源。
- **N18：关闭有界。** 应用关闭时必须停止新的 Worktree 准入，并在配置的有界时间内尝试取消、结算和释放租约。超时任务必须保留工作区并记录未完成结算，不能通过强制删除换取快速退出。
- **N19：外部故障隔离。** Git 不可用、仓库损坏、锁竞争、初始化失败或清理器异常只能使相关隔离任务失败或保留，不能导致普通对话、非隔离子 Agent 和应用进程崩溃。
- **N20：远端状态保守。** 网络不可达、远端删除、远端引用陈旧和认证失败不得被解释为“已经推送”。本功能不得为了自动清理而要求网络可用。

### 并发与跨进程行为

- **N21：仓库级协调。** 同一仓库中的多个子 Agent 和多个 XAgent 进程必须通过共同的仓库级协调机制保护 Git 公共状态、分支命名空间、工作区索引和删除租约。
- **N22：任务级隔离。** 一个工作区的创建失败、初始化失败、锁等待、结算或清理不得阻塞无关仓库中的任务；同一仓库中互不冲突的 Agent 执行阶段应保持并行。
- **N23：锁有界。** 所有跨进程锁和进程内锁必须有明确的获取顺序、超时、取消和失效处理。不得依靠无限等待或仅依靠 PID 存活判断处理遗留锁。
- **N24：清理让路。** 后台清理与前台任务竞争资源时必须优先跳过候选，不得长时间阻塞任务创建、工具执行、结算或应用交互。
- **N25：当前容量兼容。** Worktree 生命周期至少支持现有子 Agent 并发和排队上限，不得因为一个隔离任务而将所有子 Agent 执行退化为全局串行。

### 性能与资源治理

- **N26：增量检查。** 快速恢复、变更保护和后台扫描应优先读取有界元数据和目标状态，不得在每次任务进入时无条件遍历整个仓库或读取所有文件内容。
- **N27：初始化有界。** 复制和指纹计算必须流式进行，并受单文件、总字节、文件数、目录深度和执行时间预算限制；不得把大型依赖通过复制规则无界加载到内存。
- **N28：后台预算。** 清理器的候选数、总执行时间和并发度必须可配置且受硬上限约束。达到预算后应保存扫描进度或在下一轮重新安全评估，不得延长本轮直至扫描完成。
- **N29：无全局缓存抖动。** 创建、进入和退出 Worktree 不得清空全局文件缓存、Prompt 缓存、项目指令缓存或 Memory 缓存；缓存隔离带来的额外开销应限制在当前任务和当前工作区。
- **N30：资源及时释放。** 创建失败、准入失败、任务结算和安全删除后，文件句柄、Git 子进程、锁、租约、事件订阅和任务级缓存必须在有界时间内释放。
- **N31：可配置超时。** Git 操作、锁等待、初始化、只读恢复检查、结算和后台扫描必须分别具有合理默认超时；超时只中止当前阶段并进入安全保留或失败状态。

### 兼容性

- **N32：未启用时零行为变化。** 未声明 `isolation: worktree` 的角色、Defined 任务和无隔离角色的 Fork 任务必须保持现有项目目录、工具、Prompt、权限、缓存和生命周期行为，并且不得执行 Worktree Git 操作。
- **N33：现有功能不退化。** 普通对话、Plan Mode、Skill、权限确认、Memory、MCP、Hook、会话保存与恢复、前后台任务和结果回流在未启用 Worktree 时必须与当前基线一致。
- **N34：Git 标准兼容。** 本功能创建的目录和分支必须保持为标准 Git Worktree 和普通本地分支，用户可以使用标准 Git 命令查看、提交、推送、合并和人工处理。
- **N35：不修改用户历史。** 系统不得自动改写已有 commit、强制移动用户分支、删除远端引用、改变主工作目录当前分支或修改用户全局 Git 配置。
- **N36：Hook 隔离兼容。** 启用 Worktree 专属 Git hooks 不得改变其他 Worktree 行为；启用任务级 runtime hooks 不得改变非隔离任务现有事件与执行目录。
- **N37：Provider 无关。** Worktree 隔离不得依赖特定 LLM Provider。不同模型和 Provider 应使用同一工作区身份、工具能力、路径边界和结算规则。
- **N38：配置向后兼容。** 未包含 Worktree 配置的现有配置文件必须继续有效；新增字段的默认值不得隐式启用隔离、复制文件、创建软链或开放外部路径。

### 平台与文件系统兼容性

- **N39：支持当前目标平台。** 本功能应在 XAgent 当前支持的桌面和服务器平台上使用平台等价的安全路径、锁和子进程原语。某平台无法提供所需安全保证时，Worktree 隔离必须明确不可用并失败关闭。
- **N40：文件系统差异安全。** 路径身份和冲突判断必须考虑大小写敏感性、符号链接、路径别名、挂载点、设备边界和平台路径格式差异，不能假设所有文件系统具有相同语义。
- **N41：Git 能力检测。** 启动或首次使用时必须检测所需 Git 与 Worktree 能力。版本或仓库格式不受支持时，只禁用隔离能力并给出可操作诊断，不影响其他 XAgent 功能。
- **N42：无全局副作用。** 平台适配不得修改用户 Shell 配置、全局环境变量、全局 Git 配置或系统级安全策略。

### 可观测性与诊断

- **N43：稳定错误分类。** 创建、恢复、路径校验、初始化、工具过滤、锁、租约、Git 检查、变更保护、结算和清理必须使用稳定的机器可读错误类别。
- **N44：可操作诊断。** 错误应说明当前阶段、是否创建了资源、是否保留、是否允许重试，以及用户下一步应检查什么；不得要求用户从原始 Git stderr 猜测生命周期状态。
- **N45：生命周期可追踪。** 每个工作区的状态转换必须产生有界事件，并携带稳定工作区标识和安全修订号，使 TUI、任务结果和后台清理记录能够关联同一资源。
- **N46：工具过滤透明。** 因不支持任务工作区或无法落实项目写边界而被移除的工具，应在任务准备诊断中按安全类别汇总；不得静默让模型误以为工具仍然可用。
- **N47：清理可审计。** 每次自动删除都必须能够回答“删除了哪个稳定工作区、通过了哪些保护检查、何时删除、结果如何”，同时不记录敏感文件内容和非必要绝对路径。
- **N48：诊断有界。** 高频锁竞争、重复扫描和大量无效目录不得生成无界日志；相同错误应限频、聚合并记录丢弃数量。

### 可测试性与交付质量

- **N49：依赖可替换。** Git 操作、时钟、身份生成、锁、文件系统边界、进程状态和工具能力判断必须可在测试中替换或故障注入，不依赖真实远端和用户全局配置。
- **N50：真实 Git 验证。** 除单元测试外，必须使用临时真实 Git 仓库验证 Worktree 创建、只读恢复、dirty 检查、远端跟踪判断、分支删除、嵌套目录和 Git hooks 行为。
- **N51：并发验证。** 必须验证同任务重复操作、多任务并行、两个进程竞争、清理与进入竞争、遗留租约和仓库锁超时，确保没有重复资源、误删和死锁。
- **N52：崩溃故障注入。** 必须在创建、初始化、发布可用状态、任务准入、进入、终态、删除目录和删除分支等阶段注入中断，并验证下一次启动能安全分类和处理残留状态。
- **N53：安全回归验证。** 必须覆盖路径遍历、符号链接替换、大小写碰撞、保留名称、初始化源替换、ignored 文件修改、无 upstream commit、伪造元数据和未知工具能力等场景。
- **N54：完整验收后交付。** 本功能可以在技术计划中分层实现，但角色触发、Worktree 生命周期、任务级运行时、初始化、结算保护和后台清理全部通过验收前，不得宣称整个 Spec 已完成。
- **N55：代码质量基线。** 实现完成后必须通过格式化、静态检查、单元测试、并发检测、构建和真实终端端到端验证；不得以仅通过模拟测试代替真实 Git 与 TUI 场景。

## 不做的事

- **不负责代码合并。** 本功能不自动执行 merge、rebase、cherry-pick、squash、冲突解决或提交选择。子 Agent 完成后，上层或用户根据返回的分支和工作区信息决定如何整合代码。
- **不负责跨目录代码同步。** 主工作目录的未提交修改不会复制到子 Worktree；子 Worktree 的修改也不会实时同步到主工作目录、其他 Worktree 或其他子 Agent。
- **不提供可写共享依赖。** 需要写入的依赖、缓存、生成目录和构建目录不通过软链跨任务共享；本功能不实现写时复制文件系统或共享目录并发协调。
- **不做多 Agent 团队编排。** 本功能不决定子 Agent 之间的任务依赖、执行顺序、结果汇总、角色协作、失败重试策略或分支合并顺序。
- **不提供任意 Git 基准选择。** Worktree 固定基于委派准备时的当前 `HEAD` commit 创建；本轮不支持由模型或调用方选择其他 branch、tag、commit 或远端引用作为起点。
- **不继承主目录 dirty 状态。** 主工作目录中的暂存、未暂存和未跟踪内容不会被快照、复制或应用到子 Worktree。
- **不自动提交或推送。** 生命周期管理不会自动执行 add、commit、amend、push、fetch、pull、设置 upstream 或创建 Pull Request。
- **不删除远端内容。** 无论任务状态和过期时间如何，系统都不自动删除远端分支、远端 tag、远端 commit 或托管平台资源。
- **不绕过变更保护。** 本轮不提供自动强制删除、过期后强制回收或模型参数触发的丢弃模式。用户需要先在系统外明确处理未提交修改和未推送 commit。
- **不接管手工 Worktree。** XAgent 不自动发现、导入、修复、移动、重命名或删除用户通过 Git 手工创建的 Worktree 和分支。
- **不提供通用 Worktree 管理器。** 本功能只服务于声明 Worktree 隔离的子 Agent 任务，不扩展为面向用户的完整 Git Worktree CLI 或分支管理产品。
- **不允许调用参数覆盖角色隔离。** 委派请求不能临时开启、关闭或切换角色的隔离模式；隔离要求只来自已验证的角色定义。
- **不强制隔离所有子 Agent。** 未声明 `isolation: worktree` 的角色和未附带隔离角色的 Fork 任务继续使用现有共享项目目录。
- **不改变主 Agent 工作目录。** 主 Agent 保持在应用启动时的项目根运行；本功能不为主 Agent 自动创建 Worktree，也不通过进程级 `chdir` 改变主 Agent 目录。
- **不在仓库外创建受管 Worktree。** 本轮不支持用户自定义任意 Worktree 根目录、系统临时目录、远程磁盘或其他仓库外路径。
- **不自动发现初始化文件。** 系统不根据文件名猜测 `.env`、本地配置、依赖目录或被忽略运行文件；只执行项目显式白名单规则。
- **不自动安装依赖。** 环境初始化只复制、链接或配置已声明对象，不自动运行包管理器、构建脚本、下载器或项目安装命令。
- **不自动修复初始化状态。** 快速恢复发现初始化文件缺失、被修改或指纹不一致时，只拒绝恢复并保留现场，不重新复制或覆盖。
- **不恢复中断的 Agent 执行。** 应用重启后可以识别、结算、保留或安全清理遗留工作区，但不会恢复子 Agent 的消息循环、模型请求、工具调用进度或后台任务。
- **不提供跨会话后台任务恢复。** 工作区持久状态只用于资源安全和崩溃一致性，不把现有进程内 SubAgent 扩展为持久任务队列。
- **不构建恶意进程安全沙箱。** 本功能阻止正常 XAgent 工具把项目修改写入主工作目录或其他 Worktree，但不承诺抵御同一操作系统用户权限下专门设计的恶意程序。
- **不提供容器或虚拟机隔离。** 本轮不引入 Docker、虚拟机、远程开发环境、独立用户账号或远程执行节点。
- **不允许不安全工具降级运行。** 无法证明支持任务工作区、无法落实项目写边界或能力未知的工具会被过滤，而不是继续绑定主工作目录运行。
- **不重新定义现有权限系统。** Worktree 隔离继续使用现有权限、Plan Mode、Hook 和命令安全规则；本轮只增加任务工作区边界，不设计新的通用授权模型。
- **不改变非隔离任务的缓存语义。** 不通过全局清缓存解决隔离问题，也不重构与项目路径无关的用户级缓存和 Provider 缓存。
- **不保证所有平台都降级可用。** 某平台无法提供所需的安全路径、锁或进程保护原语时，Worktree 隔离在该平台失败关闭，不退化为仅设置 `cwd` 的弱隔离。

## 验收标准

### 角色声明与任务归属

- **AC1（F1–F2、N38）：** 分别加载未声明 `isolation`、声明 `isolation: worktree`、显式 `shared`、空值、未知字符串和非字符串的角色；观察只有 `worktree` 被接受为显式隔离值，字段省略保持现有行为，其余定义被拒绝并产生脱敏诊断。
- **AC2（F2–F3）：** 分别提交隔离角色的 Defined 任务、附带隔离角色的 Fork 任务、无角色 Fork 任务和非隔离角色任务；观察前两者获得独立 Worktree，后两者保持共享项目目录。
- **AC3（F3–F6）：** 并行提交两个使用同一隔离角色的任务；观察其工作区身份、目录和本地临时分支均不同。中断应用并重启后，系统能识别两个遗留工作区，但不会恢复模型执行或把任务标记为继续运行。

### 受控根、忽略规则与名称安全

- **AC4（F7–F9、N32）：** 在主工作目录 clean 的仓库中创建并删除隔离任务；全过程观察主目录 Git 状态不因受管 Worktree 出现未跟踪路径，角色、Skill 和其他 `.xagent` 内容仍正常可见且不被扩大的忽略规则隐藏。
- **AC5（F8–F9）：** 在受控根未被精确忽略、被 Git 跟踪或忽略规则覆盖范围过大的仓库中尝试创建；观察创建在任何 Worktree 或分支产生前失败，并且系统不修改或提交项目忽略文件。
- **AC6（F10–F14、N40）：** 对合法嵌套名称及空段、`.`、`..`、`.git`、`.lock`、绝对路径、反斜杠、控制字符、超长段、超深路径和大小写等价冲突运行校验；观察合法名称得到稳定映射，非法名称在任何文件系统或 Git 修改前被拒绝。
- **AC7（F15–F17、N1–N4）：** 将目标父目录或中间路径替换为符号链接，并在“检查后、操作前”注入路径替换竞态；观察创建、恢复和删除均失败关闭，仓库外目标、主工作目录和其他 Worktree 未发生修改。

### 创建、基准 commit 与生命周期持久化

- **AC8（F18–F20）：** 在主目录同时存在暂存、未暂存和未跟踪修改时创建隔离任务；观察创建成功，子 Worktree 的初始树严格等于创建锁内解析出的 `HEAD` commit，且不包含主目录 dirty 内容。
- **AC9（F18–F20、N41）：** 分别在非 Git 目录、unborn `HEAD`、无法解析为 commit 的 `HEAD`、不支持 Worktree 的 Git 环境和目标分支冲突场景创建；观察相关隔离任务失败且不留下可用工作区，普通 XAgent 功能仍可运行。
- **AC10（F21–F24、N14–N17）：** 在登记创建意图、创建分支、添加 Worktree、初始化、发布可用状态和删除阶段分别注入进程中断；重启后观察每个残留资源都被分类为可安全继续、可安全回滚、部分完成或需要人工处理，没有半写元数据被当作成功状态。
- **AC11（F25–F26、N21–N25）：** 从两个 XAgent 进程并发创建同一工作区，并并发创建多个不同工作区；观察同一身份只产生一个目录和一个分支，冲突请求得到明确错误，不同工作区在 Git 公共状态操作之外仍可并行，无死锁和无限等待。

### 只读快速恢复

- **AC12（F27–F28）：** 对一个完整、可恢复的现有工作区执行快速恢复，并记录所有 Git 调用和文件系统写操作；观察只出现允许的只读 Git 查询和文件读取，不出现创建、修复、prune、配置修改、引用修改、重新初始化或其他写操作。
- **AC13（F29–F31）：** 分别篡改权威元数据、工作区标记、`.git` 指向、分支 tip、Worktree 注册、仓库身份和目录路径，再尝试恢复；观察每种不一致都被拒绝，系统不接管、不修复、不删除现场。
- **AC14（F30–F32）：** 删除或修改初始化清单中的复制文件、软链和 ignored 文件后执行快速恢复；观察恢复失败，已有文件不被重新复制、覆盖或修复。

### 环境初始化

- **AC15（F33–F35）：** 配置包含复制、Git hooks、只读依赖软链和 ignored 文件补齐的显式规则；创建后观察仅声明的目标出现，未声明的 `.env`、本地文件和依赖目录未被扫描、复制或链接。
- **AC16（F35–F37、N7、N27）：** 使用路径遍历目标、源目录内符号链接、特殊文件、超大文件、过多文件、过深目录和带特殊权限位的源执行初始化；观察越界或超限规则失败关闭，特殊对象不被复制，已复制文件不扩大权限。
- **AC17（F38–F40、F49–F54）：** 创建指向允许只读依赖的软链，并分别通过内建工具和命令尝试读取与写入；观察读取按配置允许，写入被项目工作区边界拒绝。将目标改为主工作目录、其他 Worktree、Git 管理目录或可写依赖后，观察初始化失败。
- **AC18（F41、N35–N36）：** 为一个 Worktree 配置专属 Git hooks；在主目录、该 Worktree 和另一个 Worktree 中分别触发 Git 操作，观察只有目标 Worktree 使用其专属 hooks，用户全局 Git 配置和其他工作目录行为不变。
- **AC19（F42–F44）：** 在初始化每一步注入失败；若目录内容全部与初始化事务清单一致，观察系统安全回滚目录和精确本地分支；若在失败前加入未知文件或修改初始化产物，观察系统保留现场且不强制删除。
- **AC20（F40、F42、F45、N9–N13）：** 在初始化源、错误信息和环境中放入模拟密钥、密码、Token、用户私有路径和超长内容；观察日志、事件、诊断、元数据和任务结果不包含原始秘密或文件内容，输出被脱敏、限长并使用稳定工作区标识。

### 任务级运行时与工具边界

- **AC21（F46–F51）：** 同时运行主 Agent 和两个隔离子 Agent，让三者读取和修改同名项目文件；观察每个 Agent 只看到自身工作目录中的项目状态，子 Agent 修改只落入各自 Worktree，主目录和其他 Worktree 不受影响。
- **AC22（F48–F54）：** 记录工具和子进程收到的工作目录、安全根、写入能力和临时目录；观察系统进程工作目录未被全局切换，每个隔离任务获得独立绑定，且没有复用仍指向主项目根的执行对象。
- **AC23（F50–F54、N8）：** 通过正常命令尝试使用绝对路径、`..` 和符号链接写入主工作目录或其他 Worktree；观察写入被拒绝。运行专门绕过同用户权限边界的恶意程序不作为本功能成功条件，产品文档也不把该隔离描述为 OS 级沙箱。
- **AC24（F55、N36）：** 在隔离任务中触发 XAgent runtime hooks；观察 hook 事件中的项目身份、命令默认目录、项目配置来源和允许写入范围绑定当前 Worktree。无法任务化的文件系统相关 action 被禁用，非隔离任务 hook 行为不变。
- **AC25（F56–F58、N43–N46）：** 注册“工作区无关”“消费任务上下文”“固定主工作区”和“未知”四类测试工具；观察隔离任务只看到前两类中通过适配验证的工具，后两类不进入模型工具定义，伪造调用也不会执行，并产生有界、可操作的过滤诊断。
- **AC26（F59）：** 分别接入启动时绑定主目录的本地 MCP、具有远端目录无关自述但无本地授权的 MCP，以及本地可信配置声明为目录无关的 MCP；观察前两者被过滤，只有第三者可供隔离任务使用。

### Prompt、项目指令、Memory 与缓存

- **AC27（F60、F62–F64）：** 在主目录与 Worktree 中准备不同的项目指令、路径说明和项目 Memory 内容，运行 Defined 隔离任务；观察任务加载 Worktree 对应上下文，同时继续使用委派时冻结的角色定义快照。
- **AC28（F61–F64）：** Fork 一个包含主目录项目指令、项目 Memory 和路径说明的父会话；观察子任务保留父消息和目录无关上下文，但主目录绑定内容被移除或替换为 Worktree 内容。
- **AC29（F64–F65、N29）：** 让主 Agent 和两个 Worktree 对相同相对路径、项目指令和 Memory key 产生不同内容并重复读取；观察缓存命中只发生在同一绝对工作区或同一安全根身份内，进入和退出 Worktree 不触发全局缓存清空。
- **AC30（F63、F66、N9–N13）：** 检查模型私有 Prompt、TUI 任务列表、持久日志、跨任务事件和最终结果；观察只有当前任务私有 Prompt 使用绝对 Worktree 路径，其他渠道只显示稳定标识或仓库相对位置。

### 结算、终态与失败路径

- **AC31（F67–F70、N15–N19）：** 在 Worktree 创建成功后分别注入参数校验失败、任务准入关闭、队列拒绝、事件发布失败和 Runner 准备失败；观察每条路径都触发一次且仅一次结算，没有资源泄漏，也没有在结算前发布最终结果。
- **AC32（F68–F71）：** 分别让任务正常完成、失败、取消、超时、达到轮次上限、在队列中被取消和随应用关闭；观察每种路径都执行幂等结算，结算不执行 commit、push、fetch、merge、rebase 或 upstream 修改。
- **AC33（F69–F70、N18、N30–N31）：** 让任务子进程或 runtime hook 延迟退出；观察系统在有界时间内等待或取消访问者后再释放租约。若无法确认停止，则保留工作区并返回“结算未完成”，不提前报告已清理。
- **AC34（F68、F70、N16）：** 制造迟到的 Runner completion、重复取消和重复结算；观察对外只发布一个包含执行结果与工作区结算结果的一致终态，迟到事件不会静默改写终态。

### 变更保护与安全删除

- **AC35（F72–F73）：** 分别制造暂存修改、未暂存修改、冲突、intent-to-add、未跟踪文件、未知 ignored 文件、被修改的初始化文件、被替换的软链和子模块变化；观察每种状态都被识别为受保护成果并拒绝删除。
- **AC36（F74–F75、N20）：** 覆盖以下分支状态：无新 commit、存在新 commit 但无 upstream、upstream 为本地分支、远端跟踪引用不存在、远端跟踪引用不包含 tip、远端跟踪引用包含 tip、网络不可用；观察只有最后一个可证明已推送的状态允许继续安全删除，检查过程不执行 fetch、push 或网络访问。
- **AC37（F76–F78、N5、N34–N35）：** 对 dirty、未推送、clean 无提交和 clean 已推送四类工作区完成任务；观察前两类保留目录和本地分支，后两类删除目录和精确本地临时分支，远端分支、主目录当前分支和用户历史均不受影响。
- **AC38（F77–F80）：** 在删除前移动分支、让其他 Worktree checkout 临时分支、替换目录身份、抢占租约，以及在“目录已删除、分支未删除”阶段注入失败；观察危险删除被拒绝，部分完成状态被持久记录，系统不降级为递归强删。
- **AC39（F81、N43–N45）：** 检查所有任务终态；观察结果包含隔离状态、稳定工作区标识、基准 commit、临时分支、结算状态、清理状态和保留原因，不包含不必要的本机绝对路径。

### 后台过期清理

- **AC40（F82–F83）：** 使用可控时钟创建正常终态、重复扫描失败和活跃租约失效的资源；观察默认 TTL 从首次终态或最后有效租约时刻计算，读取、重复扫描和检查失败不会延后过期时间。
- **AC41（F84–F87）：** 为清理器准备路径越界、无权威元数据、仓库身份不匹配、活跃、dirty、未推送、初始化产物已改变和完全安全的候选；观察只有通过路径层、归属层和 Git/变更保护层的最后一类被删除。
- **AC42（F84–F86、N21–N24）：** 两个 XAgent 进程同时让一个进程运行任务、另一个进程扫描清理；观察清理器无法取得排他删除租约并跳过候选。任务结束后，满足全部保护条件时后续扫描才可删除。
