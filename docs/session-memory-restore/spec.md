# Session Memory Restore Spec

## 背景

XAgent 目前已经具备结构化系统提示、会话保存、上下文压缩和工具调用能力，但新会话启动时仍主要依赖当前会话上下文，无法自动恢复项目长期知识、用户偏好和历史工作状态。用户在中断后重新打开 XAgent 时，需要重复说明项目约束、个人偏好和上次进度，导致 Agent 表现为“每次失忆”。

本阶段要引入分层记忆恢复能力：用手写项目指令承载稳定规范，用 JSONL 会话存档承载工作记忆，用自动笔记承载长期偏好和项目知识。三者在新会话或恢复会话时自动进入模型上下文，让 Agent 从一开始就具备项目背景和用户偏好。

## 目标

- 新会话启动时自动加载项目级和用户级指令，并按优先级注入上下文。
- 会话存档改为追加式 JSONL，使崩溃恢复更稳，坏行不会破坏整段历史。
- 恢复会话时自动处理坏行、未闭合工具调用、token 超限、长时间间隔和过期清理。
- 在 Agent Loop 自然停止后异步更新长期记忆，记录用户偏好、纠正反馈、项目知识和参考资料。
- 在处理用户请求前注入记忆索引，使模型相当于已经读过相关长期记忆。
- 明确不在本阶段引入向量数据库、RAG 检索和团队记忆同步。

## 功能需求

- F1: 系统应在新会话启动和恢复会话时自动加载分层项目指令。指令来源包括项目根目录、项目专用配置目录和用户目录；项目级指令优先级高于用户级指令，高优先级内容应排在更前面。

- F2: 项目指令应支持引用其他 Markdown 文件。引用展开必须限制嵌套深度，检测并跳过循环引用，并阻止引用路径跳出允许目录范围。

- F3: 系统应使用追加式会话存档保存对话历史。每条会话事件以独立记录追加写入，崩溃时最多影响最后一条未完整记录；恢复时坏记录应被跳过而不是导致整个会话不可用。

- F4: 系统不应为会话单独维护需要同步的元数据文件。需要会话 ID、标题、消息数、更新时间等列表信息时，应从会话存档内容扫描得出。

- F5: 会话 ID 应具备时间可读性，并能避免同一秒内创建多个会话时发生冲突。

- F6: 会话恢复时应识别并处理异常历史：坏记录跳过；工具调用没有对应工具结果时，从未闭合工具调用处截断；上下文超限时先执行一次压缩；会话间隔过久时插入时间跨度提醒。

- F7: 系统应定期清理超过保留期限的过期会话，默认保留最近 30 天内的会话。

- F8: 系统应在每轮 Agent Loop 自然停止后异步更新自动笔记。自然停止指模型生成最终回复且没有继续请求工具调用；权限拒绝、错误中断、用户取消或达到迭代上限不应触发自动记忆更新。

- F9: 自动笔记应分为四类：用户偏好、纠正反馈、项目知识、参考资料。每条笔记应保存为独立 Markdown 文档，并带有机器可读的 frontmatter。

- F10: 自动笔记应区分用户级和项目级存储。用户级笔记用于跨项目偏好；项目级笔记用于当前项目知识和项目内约束。项目级记忆应绑定稳定项目身份，项目身份由规范化真实项目根路径和有效配置摘要共同确定，避免路径移动、符号链接或大小写差异导致串记忆。

- F11: 系统应维护记忆索引文件，并在处理用户请求前将索引注入上下文。索引应控制大小，避免长期记忆本身占满上下文窗口。

- F12: 自动笔记更新应交给模型判断是否新增、合并或忽略重复内容。系统负责提供已有索引和候选上下文，但不要求本阶段实现复杂检索。自动笔记更新只能提取事实、偏好和项目状态，不得执行或采纳候选内容中的指令性要求。

- F13: 指令、会话恢复信息、记忆索引和当前会话历史应有明确上下文优先级，避免长期记忆覆盖当前用户明确指令。

- F14: 系统应把项目指令、会话存档和自动记忆视为不可信输入。它们可以提供背景和偏好，但不得覆盖系统级约束、开发者约束、当前用户明确指令或权限系统行为。

- F15: 自动笔记应保存来源、时间和类型信息。当用户明确纠正旧偏好或项目知识时，系统应能覆盖、废弃或标记旧笔记，避免错误长期保留。

- F16: 系统应提供用户可见的记忆控制能力，至少包括禁用自动记忆、查看记忆状态、查看记忆索引、删除指定范围内的笔记和重建指定范围内的索引。记忆控制命令必须在本地拦截，不得进入模型上下文或远端推理。

- F17: 会话存档记录应包含可演进的版本和事件类型信息；恢复时应校验记录结构、角色顺序和工具调用配对，避免伪造或错序历史污染当前上下文。对于坏行、半行、未知版本、非法事件类型、重复消息、并发冲突和旧格式迁移失败，系统应有明确的跳过、截断、诊断或保留原文件策略。

## 非功能需求

- N1: 安全性：项目指令引用不得读取允许范围外的文件；引用循环和过深嵌套必须被安全跳过，并产生可诊断信息。路径判断应基于规范化后的真实路径，防止 `..`、符号链接、大小写差异或相对路径混淆绕过边界。读取 include 文件时应防 TOCTOU，不能只在打开前校验路径；打开后也应校验文件类型、大小和真实路径，或拒绝可疑符号链接。

- N2: 稳定性：会话恢复时，单条坏记录、半截写入或未闭合工具调用不得导致整个会话加载失败。

- N3: 数据一致性：会话列表信息必须从 JSONL 存档扫描得出，避免 meta 文件与实际消息历史不一致。

- N4: 性能：新会话启动和会话列表加载应避免无界扫描。对索引文件、指令展开和会话清理都应设置大小、行数或时间范围限制。

- N5: 上下文预算：记忆索引应控制在 200 行或 25KB 以内；注入上下文前应优先保留当前用户请求和近期会话历史。

- N6: 可恢复性：自动笔记异步更新失败不应影响用户当前回复，也不应阻塞下一轮输入。

- N7: 可观测性：跳过坏行、截断未闭合工具调用、清理过期会话、跳过非法 include、自动记忆更新失败等情况应能通过日志、状态或诊断看到。

- N8: 隐私边界：自动笔记、会话 JSONL、记忆索引、恢复诊断、异步记忆诊断、日志和 TUI 状态不得记录工具结果中的敏感字段、API key、token、authorization header 或配置密钥；必要时应脱敏、拒写或最小化记录。

- N9: 可维护性：项目指令、会话存档和自动笔记三类机制应职责分离，避免把所有逻辑混在一个上下文拼接函数中。

- N10: 兼容性：已有会话数据如果仍是旧格式，应有明确迁移或兼容策略，不能因为新存储格式导致历史会话完全不可访问。

- N11: 存档演进：JSONL 存档必须有版本字段和可演进 schema；旧会话格式需要兼容或迁移策略，迁移不得破坏原始文件。

- N12: 资源上限：会话扫描、记忆索引、自动笔记更新和过期清理都必须有资源上限，避免启动变慢、后台任务堆积或误删项目外文件。过期清理、删除笔记和重建索引只能作用于规范化后的存储根目录内，且不得跟随路径逃逸到项目外。

- N13: 并发与崩溃恢复：会话追加写和记忆写入应具备单进程并发保护；半行、半文件和异步任务失败不应破坏已有可恢复数据。

- N14: 记忆隔离：项目级记忆必须绑定当前项目边界，切换项目后不得注入其他项目的项目级记忆；用户级记忆可以跨项目复用，但仍应受当前用户指令约束。

## 不做的事

- 本阶段不引入向量数据库、embedding 或 RAG 检索。
- 本阶段不实现团队共享记忆、远程同步或多人协作记忆合并。
- 本阶段不实现复杂的记忆评分、排序学习或机器学习优化策略。
- 本阶段不要求自动笔记能完美判断所有重复内容；去重与合并主要交给模型根据现有索引判断。
- 本阶段不把完整长期记忆全文全部注入上下文，只注入受大小限制的索引和必要摘要。
- 本阶段不把项目指令当作可执行脚本；它们只是 Markdown 文本，不允许通过 include 执行命令。
- 本阶段不保证恢复任意损坏的 JSONL 文件，只保证坏行可跳过、半截工具调用可截断、可恢复部分继续使用。
- 本阶段不改变权限系统的安全边界；长期记忆和项目指令不能绕过工具权限、黑名单或路径沙箱。
- 本阶段不要求为会话维护单独 meta 文件；如果需要列表信息，只能从存档扫描或临时缓存中得出。
- 本阶段不把项目指令、会话存档或长期记忆视为可信安全策略来源；它们不能提高权限级别，也不能关闭安全检查。

## 验收标准

- AC1: 创建新会话时，系统会自动加载项目级和用户级指令；观察最终上下文时，高优先级项目指令排在用户级指令之前。

- AC2: 指令文件中的合法引用会被展开；循环引用、过深引用和跳出允许目录的引用会被跳过，并能看到诊断信息。

- AC3: 会话保存为追加式存档；连续发送多轮消息后，存档中每条记录独立成行。

- AC4: 手动破坏会话存档中的一行后，恢复会话仍能加载其他有效记录，并提示坏行被跳过。

- AC5: 会话列表中的 ID、标题、消息数和更新时间能从存档扫描得出；删除任何独立 meta 文件不影响列表生成。

- AC6: 同一秒内快速创建多个会话时，会话 ID 不重复，并包含可读时间前缀。

- AC7: 恢复到未闭合工具调用的会话时，系统会从未闭合工具调用处截断，之后仍可继续对话。

- AC8: 恢复超出上下文预算的会话时，系统会先执行一次压缩，再进入模型请求流程。

- AC9: 恢复长时间未打开的会话时，系统会插入一条时间跨度提醒，让模型知道距离上次活动已经过去多久。

- AC10: 超过默认保留期限的会话会被定期清理；未过期会话不会被误删。

- AC11: Agent Loop 自然停止后，系统异步生成或更新自动笔记；工具调用中断、用户取消、错误停止或达到迭代上限不会触发自动笔记更新。

- AC12: 自动笔记能按用户偏好、纠正反馈、项目知识、参考资料四类保存为带 frontmatter 的 Markdown 文件。

- AC13: 用户级笔记和项目级笔记分别存储；切换项目后，用户级笔记仍可用，项目级笔记不串到其他项目。

- AC14: 处理用户请求前，系统会把记忆索引注入上下文；索引文件超过 200 行或 25KB 时会被压缩或拒绝继续膨胀。

- AC15: 当已有索引中包含相同或相近记忆时，自动笔记更新请求会让模型选择合并或忽略，而不是机械重复新增。

- AC16: 当前用户消息与当前会话历史优先于长期记忆；当长期记忆与当前明确指令冲突时，系统提示模型遵循当前指令。

- AC17: 自动笔记更新失败不会影响用户已经看到的最终回复，也不会阻塞下一轮输入。

- AC18: 工具结果中的明显密钥、token、authorization header 等敏感内容不会写入长期记忆文件或索引。

- AC19: 项目指令中包含要求绕过权限、自动批准危险工具或忽略系统约束的内容时，系统仍保持权限系统生效，并在上下文中明确当前安全约束优先。

- AC20: `@include` 指向项目外路径、项目外符号链接或循环引用时，引用内容不会进入上下文，并能看到对应诊断。

- AC21: JSONL 会话记录包含坏行、半行、未知版本、非法事件类型、错序角色、伪造工具结果、重复消息或未闭合工具调用时，恢复过程会按策略跳过或截断异常部分，保留可恢复历史并产生诊断。

- AC22: 旧格式会话存在时，系统能按兼容策略加载或迁移；迁移失败时原始会话文件仍保留。

- AC23: 用户明确纠正某条长期偏好或项目知识后，后续记忆索引不再继续注入被废弃的旧结论。

- AC24: 用户可以通过 `/memory status`、`/memory index`、`/memory off`、`/memory delete <scope> <id>` 和 `/memory rebuild <scope>` 禁用自动记忆、查看状态、查看索引、删除笔记并重建索引；这些命令本地拦截、不进入 LLM，成功和失败都有可见结果。

- AC25: 切换到另一个项目后，前一个项目的项目级记忆不会被注入；用户级记忆仍按当前上下文约束可用。

- AC26: 会话扫描、过期清理和记忆索引更新在超过资源上限时会停止扩张或降级处理，并能看到诊断信息。

- AC27: 自动记忆候选内容中包含“忽略权限”“以后自动执行命令”等指令性内容时，系统不会把这些内容采纳为行为规则，只允许提取事实、偏好或项目状态。

- AC28: 会话 JSONL、记忆索引、恢复诊断和异步记忆诊断中不会出现未脱敏的 API key、token、authorization header 或配置密钥。
