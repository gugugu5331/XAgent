# XAgent 安全、可靠性与交付质量提升 Spec（2026-07-30）

> 状态：已批准（2026-07-30）

## 背景

当前审计确认项目存在授权绕过、权限文件保护失效、私有运行产物误提交等发布阻断问题；同时存在会话数据无法恢复或持久化、敏感信息脱敏不完整、进程及网络资源无法可靠回收、Windows 无法构建、测试不稳定、配置无效、会话操作不可达及规格验收漂移。

本次治理横跨安全、运行时、数据、产品体验、跨平台、工程交付和文档七个方面，将作为一个治理项目，按风险顺序分阶段交付，但使用统一的验收门槛。

## 目标

- G1：消除所有已确认的 P0 缺陷，确保授权不能跨命令语义复用，权限配置不能被普通工具绕过保护。
- G2：建立完整的敏感信息与网络安全边界，保证凭据不会进入模型上下文、界面、会话、诊断或日志，认证信息不会经不安全连接或重定向泄露。
- G3：为命令、文件、Instruction、MCP、Provider 和流式处理建立可执行的资源上限及可靠的取消、关闭和进程树回收行为。
- G4：保证会话记录可保存、列出、恢复和继续写入；上下文外置、元数据及配置行为在重启后保持一致。
- G5：补齐会话导航、响应式界面、状态清理、帮助和错误可见性，使所有公开配置和用户入口具有真实、可观测的效果。
- G6：恢复 Windows 构建能力，建立稳定的跨平台 CI、race、静态检查、覆盖率和端到端验证基线。
- G7：清理仓库中的私有产物和无效 gitlink，防止同类文件再次进入版本控制。
- G8：统一实现、README、规格与 checklist 的事实状态；废弃需求明确标记，不再以过期勾选项作为验收证据。

## 功能需求

### 一、仓库与发布安全

- F1：项目产生的会话、记忆、临时二进制、工作树、个人附件及其他运行产物不得进入版本控制。
- F2：提交和发布检查必须阻止疑似凭据、未声明 gitlink、超限二进制及已知私有目录进入仓库，并提供不暴露原文的诊断。

### 二、权限系统

- F3：Bash 授权必须绑定完整命令语义；空格、换行、引号或控制符不同的命令不得错误共享 once、session 或 permanent 授权。
- F4：任何普通工具、Shell、解释器、变量展开或字符串拼接都不得修改受保护的权限配置；该限制不能被规则或用户确认覆盖。
- F5：权限配置损坏时，所有危险工具——包括远程 MCP 工具——必须 fail closed，只有只读低风险能力才能按保守策略继续。
- F6：永久授权只能保存最小、明确且不含敏感信息的范围；确认界面必须展示实际目标、风险、授权范围、规则落点和撤销方式。

### 三、凭据与网络边界

- F7：所有运行期展开的 LLM、MCP、Hook 及其他凭据必须注册到同一个秘密清单，并在界面、模型上下文、会话、诊断、日志、错误和 memory 中统一脱敏。
- F8：LLM 与远程 MCP 默认只允许安全传输；非本机明文 HTTP 必须被拒绝。每次重定向都必须重新验证协议和目标，敏感请求头不得跨源传播。

### 四、工具与资源控制

- F9：命令和文件工具必须在采集阶段执行输出、文件、目录、行数和内存预算，不能等操作完成后才截断。
- F10：被截断的完整输出必须保存为本机私有 artifact；用户可以追溯，模型默认不可读取，原文不得进入会话、诊断或 memory，并支持清理策略。
- F11：Bash 超时、取消或退出时必须终止完整进程树，并在有限时间内完成资源回收。
- F12：Read、Grep、Glob 必须响应取消、报告扫描错误，并安全处理大文件、巨型目录和超长行。
- F13：Instruction 加载必须具备累计文件数、累计字节数和展开规模限制；重复 include 不得指数放大，符号链接竞争也不得读取允许根之外的内容。

### 五、Provider 与 MCP 生命周期

- F14：MCP JSON、SSE、协议错误和诊断必须受累计预算约束；超限时返回明确、脱敏且可恢复的错误。
- F15：MCP Manager 关闭后必须终止接收循环、释放 HTTP/stdio 资源、清理远端会话，并拒绝新的工具调用；状态查询与关闭并发时不得产生竞态。
- F16：stdio MCP 在成功、初始化失败、超时和退出路径都必须回收进程，持续排空但只有限保留 stderr，且不得发生关闭通道竞争或遗留阻塞写协程。
- F17：Provider 流必须在完成、错误、取消和消费者提前退出时可靠关闭底层连接；扫描错误不得被当作正常结束。
- F18：OpenAI 流必须读取标准顺序中结束原因之后到达的 usage 信息，并把准确用量交给状态显示和上下文管理。

### 六、会话与编排正确性

- F19：系统写出的每条合法会话记录都必须能够重新加载；超限或损坏记录必须产生可见诊断，不能让整个会话静默消失。
- F20：消息原地修改、上下文外置、摘要和元数据更新必须可靠持久化，即使消息数量没有变化。
- F21：会话列表读取失败必须向用户和诊断系统报告；可恢复的损坏会话仍应出现在列表中并可继续保存。
- F22：保留期限、扫描文件数、扫描字节数和时间跨度提醒配置必须真实控制生产行为。
- F23：标记为可并发的只读工具批次必须真正受控并发执行，同时保持确定的结果顺序。
- F24：工具真正启动前发生取消时，不得生成伪造或空状态的工具结果；历史必须准确区分未启动、取消和已执行。

### 七、界面、命令与配置

- F25：用户必须能从聊天返回会话列表、新建会话及切换会话，不需要退出并重启应用。
- F26：开始新请求或切换会话时，耗时、token、缓存、停止原因、错误和临时状态必须按正确边界重置。
- F27：消息区、会话列表、输入区和确认界面必须响应终端尺寸变化，并支持可靠回看长会话和处理长输入。
- F28：所有公开配置都必须可生效；显式 `false` 不得被默认值覆盖，非法负值必须报错，用户级与项目级配置按声明的优先级合并。
- F29：帮助入口必须列出用户可用的命令、快捷键、权限模式和状态/诊断入口；兼容命令的隐藏或公开状态必须与文档一致。
- F30：CLI 帮助应以成功状态输出有效用法，并提供可查询的版本信息。

### 八、跨平台、交付与规格治理

- F31：项目必须在声明支持的平台上完成构建；Windows 不得编译 Unix 专属实现，并应具备等价的安全路径处理行为。
- F32：每次变更必须自动执行格式、静态检查、单元测试、race、跨平台构建及关键端到端场景；资源敏感测试不得依赖脆弱的固定短超时。
- F33：README、规格、任务和 checklist 必须反映当前实际行为；被替代的需求明确标记，验收勾选必须附有仍可复现的证据。

## 非功能需求

### 安全与隐私

- N1：权限硬约束必须确定、不可覆盖；相同输入在相同上下文中始终得到相同决策。
- N2：固定 canary secret 在用户界面、模型输入、会话、诊断、日志、memory、测试输出和错误链中必须实现零原文泄露。
- N3：私有 artifact 是唯一允许保存完整原始工具输出的例外；必须仅限当前用户访问，不位于项目工作区，并受容量与保留期限控制。
- N4：远程通信默认采用安全传输；不安全目标、降级重定向或跨源凭据传播必须在发送敏感数据前被拒绝。

### 资源与生命周期

- N5：所有来自文件、命令、Provider、MCP、Instruction 和会话的数据都必须有可配置预算及不可绕过的硬上限；内存占用不得随无界输入无限增长。
- N6：默认内联工具输出上限保持 32 KiB；MCP 单次响应默认上限保持 1 MiB。截断必须按有效字符边界进行，并明确报告原始字节数和截断状态。
- N7：取消或超时发生后，相关进程树、网络请求和工作协程应在 2 秒内停止；无法停止时必须产生明确诊断，不能静默遗留。
- N8：关闭操作必须幂等；并发调用、重复关闭及部分初始化失败不得造成 panic、死锁、数据竞争或资源泄漏。

### 数据可靠性

- N9：会话保存必须具备崩溃安全性；写入失败不能破坏最后一份可恢复状态，也不能让已有会话从列表中静默消失。
- N10：损坏、超限或旧版本数据必须采用非破坏性恢复；迁移完成前不得删除或覆盖原始记录。
- N11：同一会话在保存、重启和恢复后，其消息、工具状态、上下文外置状态、摘要及关键元数据必须保持语义一致。

### 性能与交互

- N12：正常规模的命令、会话和配置不得因新增安全检查产生明显交互停顿；耗时操作必须可取消并展示进行中状态。
- N13：界面必须在至少 80×24 的终端中可操作，终端尺寸动态变化时不得 panic、覆盖确认信息或使输入不可达。
- N14：诊断必须简洁、可行动并标明来源；同类重复错误需要限量或聚合，不能造成界面和内存无限增长。

### 兼容性与配置

- N15：支持范围确定为 macOS、Linux 和 Windows amd64；三者必须通过构建，核心路径、权限和会话行为必须具有等价安全语义。
- N16：现有有效配置、权限规则和会话记录必须继续可用；必须破坏兼容性的变更需要显式版本、迁移说明和可恢复路径。
- N17：配置合并和默认值应用必须确定且可解释；未知字段、非法值、冲突值和无效组合必须在启动阶段报告。

### 测试与交付质量

- N18：完整测试套件连续运行 3 次不得出现随机失败；MCP stdio、取消、关闭和并发等历史敏感场景定向重复 20 次必须稳定通过。
- N19：整体自动化测试覆盖率不得低于当前约 80% 的基线；新增授权、脱敏、持久化、资源限制和生命周期分支必须有直接测试。
- N20：每次提交必须通过格式、静态检查、普通测试、并发检测、支持平台构建、敏感信息扫描及至少一个端到端场景。
- N21：默认测试不得依赖真实外部 Provider、真实凭据或公网可用性；外部集成测试必须显式启用并与普通测试隔离。
- N22：每条功能需求必须能追溯到验收标准和 checklist 条目；不存在无证据的已完成勾选，废弃条目必须明确标注替代关系。

## 不做的事

- O1：不新增 LLM Provider、MCP 协议能力、内置工具、Skill 类型或业务功能。
- O2：不把 TUI 改造成 Web、桌面 GUI 或客户端—服务器架构；只完善现有终端交互。
- O3：不提供云端 artifact、会话同步、多人协作、账号体系或跨设备共享。
- O4：不构建能够隔离任意敌意代码和整个宿主机的通用虚拟机/容器沙箱；本次只保证受保护配置、项目边界、进程树和资源预算等已声明安全约束。
- O5：不自动重写已经发布的 Git 历史，也不自动撤销外部平台凭据；若扫描确认历史泄露，只提供明确的人工处理和轮换步骤。
- O6：不对 Provider 或 MCP 服务端已经接受的远程副作用提供事务回滚保证。
- O7：不承诺恢复已经被物理删除、完全覆盖或无法解析的原始会话数据；只保证现存可读取数据的非破坏性恢复。
- O8：不支持 macOS、Linux 和 Windows amd64 之外的新平台，也不在本次建立移动端或嵌入式兼容性。
- O9：不进行与本次问题无关的模型提示词、回答质量、token 策略或 Agent 行为调优。
- O10：不为了统一风格重写全部模块；架构调整仅限满足已批准需求、消除安全缺陷和建立可验证边界。
- O11：不删除历史规格文档；过期内容采用 `superseded` 标记和替代关系保留审计轨迹。
- O12：不在本次实现自动发布、包管理器分发、代码签名或安装程序；交付范围止于可重复构建、测试和发布前检查。

## 验收标准

### 仓库与权限

- AC1（F1）：当前 35 个会话、记忆、worktree gitlink 和大型产物全部退出暂存区但保留本地数据；正常运行项目后，它们不会再次出现在待提交文件中。
- AC2（F2）：分别放入 canary secret、无映射 gitlink、私有目录文件和超限二进制，提交检查均会失败；报告不显示 secret 原文。
- AC3（F3）：先授权单行打印命令，再提交仅增加换行便会执行额外命令的碰撞样本；第二条仍须重新确认或被拒绝，且所有授权范围均不能复用。
- AC4（F4）：使用直接路径、变量、字符串拼接和解释器动态构造路径尝试修改权限配置，操作均被硬拒绝，文件内容与校验值保持不变。
- AC5（F5）：任一权限配置层损坏时，Bash、Write、Edit 和危险 MCP 均不可执行；低风险只读操作按保守策略继续，并显示配置诊断。
- AC6（F6）：含凭据的命令不能创建永久规则；安全规则只保存最小范围，确认界面能够看到目标、风险、授权范围、落点和撤销说明。

### 凭据与网络

- AC7（F7）：将同一 canary 放入 LLM key、MCP env/header、Hook、Provider/MCP 返回值和错误后，TUI、模型输入、会话、诊断、日志、memory 与测试输出均不含原文。
- AC8（F8）：非本机 HTTP Provider/MCP 在发送请求前被拒绝；HTTPS 向 HTTP、外部域名或内网地址重定向时被拒绝，目标服务收不到认证头。

### 工具与资源

- AC9（F9）：用远超限制的 stdout、stderr、文件、目录和 SSE 输入测试时，返回内容遵守配置预算，峰值缓冲不随完整输入线性增长，并产生明确的超限状态。
- AC10（F10）：超限输出生成本机私有 artifact，界面显示 ID、字节数和截断提示；原文不进入模型、JSONL、memory 或诊断，达到清理条件后可被移除。
- AC11（F11）：运行包含后台子进程和孙进程的命令并触发取消/超时，2 秒内所有后代均退出，工具不会在报告结束后继续产生副作用。
- AC12（F12）：取消 Read/Grep/Glob 会及时停止；大文件、巨型目录、超长行和底层读取错误均返回受限且可理解的结果，不遗留继续分配内存的任务。
- AC13（F13）：重复、菱形和深层 include 不会重复指数展开；超过累计预算时给出诊断；并发切换符号链接也无法读取允许根外内容。

### Provider 与 MCP

- AC14（F14）：未知长度的分块 SSE 超过累计响应预算时被中止；连续恶意协议错误只保留有限摘要，内存不会持续增长。
- AC15（F15）：HTTP MCP 启动后关闭 Manager，接收循环和连接全部退出；重复关闭成功，关闭后的调用被拒绝，并发关闭与状态查询不产生竞态。
- AC16（F16）：stdio MCP 初始化失败后进程退出；持续输出大量 stderr 不会阻塞 RPC且诊断保持有界；突发响应后退出不发生 panic；取消阻塞写不会累积协程。
- AC17（F17）：Provider 在正常完成、解析错误、网络错误、取消和消费者提前退出五种路径中都关闭底层流，并把扫描错误报告为错误而非正常结束。
- AC18（F18）：按“结束原因 → usage → 流结束”的标准顺序发送响应，最终仍产生准确 usage，状态栏和上下文估算收到相同数值。

### 会话与编排

- AC19（F19）：保存并重启加载一条超过 64 KiB、但仍在系统上限内的合法记录成功；真正超限或损坏的记录仍出现在列表中，并带安全诊断。
- AC20（F20）：加载已有会话，只修改工具外置状态、摘要或元数据后保存并重启，重新加载结果与修改后状态一致。
- AC21（F21）：模拟列表目录无权限或扫描错误，界面显示错误而非空历史；包含可恢复坏行的会话仍可打开、继续对话并再次保存。
- AC22（F22）：分别调整保留期限、扫描文件上限、扫描字节上限和时间跨度提醒，四项都产生对应且可观察的行为变化。
- AC23（F23）：同批两个阻塞型只读工具能够重叠执行，不超过并发上限，最终结果仍按原始调用顺序回灌。
- AC24（F24）：在 ToolPending 与真正启动之间取消，历史中不出现空状态结果；未启动、已取消和已执行三种情况可被准确区分。

### 界面、命令与配置

- AC25（F25）：用户不退出应用即可完成“新建会话 → 返回列表 → 恢复旧会话 → 再切换到新会话”，每次切换前旧会话可靠保存。
- AC26（F26）：完成一轮请求后开始下一轮，并随后切换会话；旧耗时、token、缓存、停止原因、错误和临时状态均不会串入新边界。
- AC27（F27）：在 80×24、宽屏和运行中动态缩放三种终端环境下，长输入、长消息、确认面板和历史滚动均可操作且不发生布局破坏或 panic。
- AC28（F28）：显式关闭计时后界面不显示耗时；各负数配置启动失败；用户、项目及运行期配置按照声明优先级产生确定结果。
