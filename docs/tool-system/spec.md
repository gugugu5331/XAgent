# XAgent Tool System Spec

## 背景
XAgent 当前已经具备终端 TUI、多轮对话、流式模型响应、会话持久化、Anthropic Claude 和 OpenAI 双 Provider 的基础能力。但当前模型只能生成文字回复，不能实际读取项目、修改文件、搜索代码或执行命令，因此还不是能完成工程任务的 Agent。

本阶段目标是在现有纯对话能力之上加入工具系统。用户提问后，模型可以根据任务需要发起工具调用；XAgent 解析模型流式返回的工具调用参数，执行本地工具，把结构化结果回灌进对话历史，让模型基于工具结果给出后续回复或说明。本阶段先实现一次工具调用结果回灌，不实现自动多轮 Agent Loop。

工具调用过程需要在 TUI 中以接近 Claude Code 的工具行形式呈现，例如 `● Read(path)`、`● Grep(pattern)`、`● Bash(command)`，并在工具完成后展示简短结果摘要，使用户能清楚看到模型正在使用哪个工具、参数是什么、执行结果如何。

## 目标
- 提供统一的 Tool 接口，所有工具通过同一抽象描述和执行。
- 提供工具注册中心，集中登记工具、按名称查找工具，并转换为 LLM API 可识别的工具定义。
- 首版提供六个核心工具：读文件、写文件、改文件、执行命令、按模式找文件、搜索代码内容。
- 支持 Anthropic Claude 和 OpenAI 两类 Provider 的工具调用协议。
- 支持解析流式工具调用，包括 JSON 参数碎片拼接。
- 支持执行工具并把结构化结果回灌进对话历史。
- 在 TUI 中以 Claude Code 风格工具行展示工具调用和结果摘要。
- 支持工具执行超时、错误处理和结构化失败结果。
- 文件和命令工具默认限制在项目根目录内，避免越界访问。
- 写文件、改文件、执行命令属于危险操作，执行前需要用户在 TUI 中确认。
- 改文件工具使用原文唯一匹配替换，匹配不到或匹配多次时返回清晰错误。
- 本阶段不实现自动连续工具调用循环；模型拿到一次工具结果后，本轮停止在一次结果回灌后的回复。

## 功能需求
- F1: 系统提供统一的工具抽象，每个工具都包含名称、描述、参数 Schema 和执行能力。
- F2: 系统提供工具注册中心，可以集中登记工具。
- F3: 系统可以通过工具名称查找对应工具。
- F4: 系统可以把已注册工具转换为 Anthropic Claude API 可识别的工具定义。
- F5: 系统可以把已注册工具转换为 OpenAI API 可识别的工具定义。
- F6: 系统首版内置读文件工具，模型可以请求读取项目内指定文本文件内容。
- F7: 系统首版内置写文件工具，模型可以请求在项目内写入指定文件内容。
- F8: 系统首版内置改文件工具，模型可以请求在项目内把唯一匹配的原文替换为新内容。
- F9: 系统首版内置执行命令工具，模型可以请求在项目根目录内执行 shell 命令。
- F10: 系统首版内置按模式找文件工具，模型可以请求按 glob 模式查找项目内文件。
- F11: 系统首版内置搜索代码内容工具，模型可以请求在项目内按文本或正则搜索文件内容。
- F12: 文件相关工具只能访问项目根目录内路径；路径越界时必须拒绝执行并返回结构化错误。
- F13: 命令执行工具只能在项目根目录内运行命令。
- F14: 写文件、改文件和执行命令在执行前必须向用户请求确认。
- F15: 用户拒绝危险工具执行时，系统不执行该工具，并把拒绝结果作为结构化工具结果返回给模型。
- F16: 工具执行需要支持超时；超时后停止等待并返回结构化工具结果。
- F17: 工具执行失败时，包括文件不存在、路径越界、命令超时、命令非零退出、改文件匹配不到、改文件匹配多次、搜索无结果、参数格式错误等情况，系统必须把失败原因包装成结构化工具结果回灌给模型，使模型可以基于失败信息调整后续回复。
- F18: 工具执行失败时，程序不能崩溃，会话不能中断，用户仍可以继续对话或退出。
- F19: 工具执行失败时，TUI 需要以可区分样式展示失败状态和简短错误摘要。
- F20: 改文件工具必须使用原文唯一匹配替换。
- F21: 改文件工具在原文匹配不到时必须返回清晰的结构化错误结果。
- F22: 改文件工具在原文匹配多次时必须返回清晰的结构化错误结果。
- F23: Anthropic Claude Provider 能在流式响应中识别工具调用开始、工具名称和工具调用 ID。
- F24: Anthropic Claude Provider 能在流式响应中拼接工具调用 JSON 参数碎片。
- F25: OpenAI Provider 能在流式响应中识别工具调用开始、工具名称和工具调用 ID。
- F26: OpenAI Provider 能在流式响应中拼接工具调用 JSON 参数碎片。
- F27: Provider 层需要把不同后端的工具调用事件统一成上层可消费的工具调用事件。
- F28: TUI 在模型请求工具时显示 Claude Code 风格工具行，例如 `● Read(path)`、`● Write(path)`、`● Edit(path)`、`● Bash(command)`、`● Glob(pattern)`、`● Grep(pattern)`。
- F29: TUI 在工具执行中显示该工具处于进行中状态。
- F30: TUI 在工具完成后显示简短结果摘要，例如读取了多少字节、写入哪个文件、替换成功、命令退出码、匹配到多少文件或多少行。
- F31: TUI 在工具失败后显示简短错误摘要。
- F32: TUI 在危险工具执行前显示确认提示，用户可以允许或拒绝。
- F33: 工具执行结果需要被追加到当前会话历史，使模型能够看到工具结果。
- F34: 工具结果回灌后，模型可以基于工具结果生成一次最终回复。
- F35: 本阶段只支持一次工具调用结果回灌；完成一次工具结果回灌和最终回复后，本轮结束。
- F36: 如果模型在最终回复中再次请求工具调用，系统不继续自动执行，并提示该能力留到后续 Agent Loop 阶段。
- F37: 没有工具调用的普通对话仍保持现有流式回复体验。
- F38: 工具系统不能暴露 tool use、文件操作、命令执行之外的额外能力。

## 非功能需求
- N1: 工具系统继续使用 Go 实现，并集成到现有 XAgent 架构中。
- N2: 工具执行默认限制在项目根目录内，所有文件路径在执行前必须规范化并检查是否越界。
- N3: 工具执行错误必须以结构化结果表示，不能只依赖纯文本错误字符串。
- N4: 工具结果应同时适合模型消费和用户阅读；模型获得完整结构化结果，TUI 展示简短摘要。
- N5: 工具执行必须有默认超时时间，避免长时间阻塞 TUI。
- N6: 命令执行必须捕获 stdout、stderr、退出码和超时状态。
- N7: 文件读取和搜索结果需要限制单次返回大小，避免把过大的内容一次性塞入模型上下文。
- N8: 工具参数 Schema 应保持稳定，便于不同 Provider 转换和后续扩展。
- N9: Provider 层应隐藏 Anthropic Claude 和 OpenAI 的工具调用协议差异，上层只处理统一工具调用事件。
- N10: 普通无工具对话的现有体验不能退化，包括流式输出、多轮上下文和会话保存。
- N11: TUI 工具行应保持紧凑、可读，并与普通 assistant 回复区分。
- N12: 危险工具确认提示必须清晰展示工具名称、关键参数和潜在影响。
- N13: 用户拒绝危险工具后，系统必须把拒绝作为正常工具结果处理，而不是异常崩溃。
- N14: 本阶段不实现自动多轮 Agent Loop，避免无限工具调用或不可控执行。
- N15: 工具结果写入会话历史时，应避免保存不必要的大量输出；超过限制的内容需要截断并标记。
- N16: api_key 等敏感配置不得出现在工具行、工具结果摘要或错误信息中。

## 不做的事
- 不实现自动多轮 Agent Loop。
- 不在一次用户请求中连续自动执行多个工具调用轮次。
- 不实现并行工具调用。
- 不实现工具权限持久化记忆，例如“以后都允许这个命令”。
- 不实现项目外路径访问。
- 不实现网络访问工具、浏览器工具、HTTP 请求工具或 MCP 工具。
- 不实现 Git 专用工具、PR 工具或 Issue 工具。
- 不实现工具调用审计日志系统。
- 不实现复杂沙箱、容器隔离或系统级权限隔离。
- 不实现二进制文件编辑。
- 不实现图片、PDF、Notebook 等富媒体读取。
- 不实现上下文压缩、工具结果摘要记忆或长期知识库。
- 不改变现有配置文件中的 LLM 四个核心字段语义。
- 不改变普通无工具对话的基本体验。

## 验收标准
- AC1: 系统存在统一工具抽象，工具具备名称、描述、参数 Schema 和执行能力。
- AC2: 系统存在工具注册中心，可以登记工具并按名称查找工具。
- AC3: 注册中心能输出 Anthropic Claude 可用的工具定义。
- AC4: 注册中心能输出 OpenAI 可用的工具定义。
- AC5: 读文件工具可以读取项目内文本文件内容。
- AC6: 读文件工具访问项目外路径时返回结构化错误结果。
- AC7: 写文件工具在用户确认后可以在项目内写入文件。
- AC8: 写文件工具在用户拒绝后不写文件，并返回结构化拒绝结果。
- AC9: 改文件工具在原文唯一匹配时可以完成替换。
- AC10: 改文件工具在原文匹配不到时返回结构化错误结果。
- AC11: 改文件工具在原文匹配多次时返回结构化错误结果。
- AC12: 执行命令工具在用户确认后可以在项目根目录运行命令。
- AC13: 执行命令工具返回 stdout、stderr、退出码和超时状态。
- AC14: 执行命令工具超时时返回结构化错误结果，程序不崩溃。
- AC15: 按模式找文件工具可以按 glob 模式返回项目内匹配文件。
- AC16: 搜索代码内容工具可以返回项目内匹配内容的位置和摘要。
- AC17: 搜索无结果时返回结构化工具结果，模型可据此调整，程序不崩溃。
- AC18: Anthropic Claude Provider 能把流式工具调用转换成统一工具调用事件。
- AC19: OpenAI Provider 能把流式工具调用转换成统一工具调用事件。
- AC20: Provider 能正确拼接 JSON 参数碎片。
- AC21: 工具执行结果会被追加到当前会话历史。
- AC22: 工具结果回灌后，模型能基于工具结果生成一次最终回复。
- AC23: 本阶段不会在一次用户请求中自动连续执行第二轮工具调用。
- AC24: 普通无工具对话仍能流式输出。
- AC25: TUI 在工具调用开始时显示 Claude Code 风格工具行，例如 `● Read(path)`。
- AC26: TUI 在工具执行中显示进行中状态。
- AC27: TUI 在工具成功后显示简短结果摘要。
- AC28: TUI 在工具失败后以可区分样式显示错误摘要。
- AC29: TUI 在写文件、改文件、执行命令前显示确认提示。
- AC30: 用户拒绝危险工具时，TUI 显示拒绝状态，会话不中断。
- AC31: 工具结果和工具行不显示 api_key 等敏感配置。
- AC32: 工具输出过大时会截断并标记，而不是无限制写入会话历史。
