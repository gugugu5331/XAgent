# 子 Agent 委派与后台任务系统 Spec

## 背景

XAgent 已具备多轮 Agent Loop、统一工具注册与执行、权限决策、Skill 的 Markdown/YAML 发现、独立临时执行、流式事件和会话存储。现有“独立执行”主要服务于固定 Skill：缺少一个稳定的统一委派入口，也没有把子 Agent 的角色、上下文继承、工具约束、权限状态和后台生命周期统一起来。

当主 Agent 需要把代码阅读、测试、审查或其他可并行工作交给专门角色时，目前存在三类问题：

1. 子任务只能依赖特定调用路径，无法用一个稳定的工具契约区分“按角色从零开始”和“继承当前上下文”的两种执行方式。
2. 子任务若共享主会话消息、授权状态或计量状态，容易造成上下文污染、权限串用和用量归属不清。
3. 长任务会阻塞当前交互；任务完成后的结果、错误、取消和用量也没有统一的可查询、可通知生命周期。

本功能建立统一的子 Agent 运行层：定义式子 Agent 从标准环境和角色指令启动，Fork 式子 Agent 在委派瞬间复制父上下文快照；两者都在隔离的运行时状态中执行，并通过后台任务管理器和事件流将进度与最终结果送回主 Agent 和 TUI。

## 目标

- 提供一个稳定的统一 Agent 委派入口，同时支持模型工具调用和用户显式入口。
- 用带 YAML frontmatter 的 Markdown 角色定义子 Agent 的身份、职责、工具约束、模型、轮次上限和权限模式；支持项目、用户、内置、插件四级来源及确定性覆盖。
- 明确定义两条启动路径：
  - 定义式：无父会话消息，使用标准系统/安全环境、项目指令和固定角色正文启动。
  - Fork 式：在委派时复制父会话消息、当时的系统环境和已过滤工具集合；Fork 强制进入后台。
- 隔离子 Agent 的消息、会话授权/确认、文件读取缓存和 Token 用量；共享 LLM 客户端、Hook 引擎和文件系统等基础设施。
- 让子 Agent 以非交互“跑到底”方式执行，模型不再请求工具即完成，并异步回流结构化结果、状态、错误和用量。
- 通过全局禁止、角色收窄和后台白名单的多层过滤，防止越权调用与无限嵌套。
- 提供前台运行、显式后台、超时自动后台和手动切后台的统一任务体验，以及任务查看、取消和结果查看能力。
- 保持现有普通对话、权限确认、Plan Mode、Skill、会话保存和脱敏边界不退化。

## 功能需求

### 统一委派入口

- **F1：** 系统提供一个稳定的 Agent 委派入口；该入口同时可被主 Agent 作为模型工具调用，也可被用户通过 TUI 的显式入口调用。两种调用使用相同的参数校验、权限检查、任务登记、事件流和结果回流规则。
- **F2：** 委派请求必须包含非空任务内容和执行类型；执行类型只有 `defined`（定义式）与 `fork`（Fork 式）。
- **F3：** `defined` 请求必须指定一个当前有效的角色；`fork` 请求可以不指定角色，也可以指定一个角色作为附加指令与收窄约束。未知角色、非法类型、空任务或超出参数限制时，系统不启动子 Agent，而是返回可恢复的结构化错误。
- **F4：** 委派请求可以声明前台或后台意图；未声明时使用默认的短任务前台策略。Fork 式请求无论请求参数如何都必须进入后台任务生命周期。

### 角色定义与加载

- **F5：** 每个角色由一个 Markdown 文档组成：YAML frontmatter 提供角色元信息，正文必须非空并作为角色的完整系统指令，伴随该角色执行的每一轮模型请求。
- **F6：** frontmatter 必须支持角色名、用途说明、工具白名单、工具黑名单、模型选择、最大轮次和权限模式。模型选择只能是 `inherit`、`haiku`、`sonnet` 或 `opus`；权限模式只能是 `inherit`、`strict`、`default` 或 `permissive`；最大轮次为非负整数。未知字段、非法值、空名称、空说明或空正文的角色定义视为无效。
- **F7：** 角色名称按大小写不敏感方式规范化，并作为唯一身份；规范化后的名称必须能安全用于委派参数和 TUI 展示。
- **F8：** 系统从项目级、用户级、内置和插件提供者四类来源收集角色，生效优先级固定为：项目级 > 用户级 > 内置 > 插件。插件通过来源提供者注册已验证的角色定义，不要求角色加载器了解插件内部存储方式。
- **F9：** 高优先级来源的同名有效角色覆盖低优先级角色；高优先级的无效定义不得遮蔽低优先级有效定义，并必须产生脱敏诊断。同一来源出现多个有效同名角色属于配置冲突；初始加载失败，运行中刷新则拒绝候选快照并继续使用上一份有效快照。
- **F10：** 角色加载结果必须以完整、不可部分发布的快照提供给委派入口；快照中包含最终生效角色、来源信息、校验诊断和可用模型/工具元信息。
- **F11：** 角色指定的模型别名必须映射到当前 Provider 可用的具体模型；无法映射时，委派准备失败并说明角色和别名，不能静默使用其他模型。
- **F12：** 角色指定的权限模式只能继承或收紧父上下文的有效模式，不能放宽父策略；角色正文、元信息和诊断均受现有脱敏规则约束。

### 两种启动路径与运行时隔离

- **F13：** 定义式子 Agent 从空白子会话启动，但必须包含应用标准系统/安全指令、项目指令、角色正文和委派任务；不得携带父会话消息或父会话当前激活的 Skill。
- **F14：** Fork 式子 Agent 在委派成功准备的瞬间复制父会话的不可变消息快照、当时有效的系统环境和已过滤工具集合；父会话之后的变化不得影响该子任务。若附加角色，角色指令只能追加提示并进一步收窄能力。
- **F15：** 每个子 Agent 必须拥有独立的运行时状态，至少包括消息历史、会话级临时授权与确认队列、文件读取缓存、Token 用量计数、循环进度和任务取消状态。子 Agent 的状态变化不得直接修改父会话或其他子任务。
- **F16：** 子 Agent 与主 Agent 共享 LLM 客户端、Hook 引擎和项目文件系统等基础设施；共享基础设施不得导致运行时状态、授权临时规则或计量数据互相覆盖。
- **F17：** 子 Agent 的权限决策仍使用现有硬安全检查、项目/用户规则和确认流程；父会话的本次允许或本会话允许不自动继承，子 Agent 的临时授权只在该任务内有效。
- **F18：** 子 Agent 不能再次调用 Agent 委派入口启动孙 Agent；此类请求必须生成可恢复的拒绝结果，并且不能创建新任务或新的后台队列项。

### 执行与停止

- **F19：** 子 Agent 以非交互模型循环运行：持续请求模型、执行允许的工具并回写结果，直到模型不再请求工具、达到有效最大轮次、被取消、发生 Provider/工具致命错误或触发其他明确停止条件。模型不再请求工具时任务状态为正常完成。
- **F20：** 有效最大轮次取全局 Agent Loop 上限与角色最大轮次（如有）的较小值；达到上限后不得继续请求模型，并记录可观测停止原因。
- **F21：** 危险工具需要确认时，子任务暂停在等待确认状态；TUI 显示带任务标识的确认卡片，用户处理后继续或拒绝。确认过程不改变子 Agent 的非交互模型循环，也不继承父任务的选择。
- **F22：** 用户取消、任务级取消或应用关闭时，系统停止该子 Agent 后续的模型请求和新工具启动；已开始的工具按现有取消与收尾语义处理。应用关闭必须在有界时间内结束所有子任务。
- **F23：** Provider 流错误、工具系统不可恢复错误或内部运行时错误不得崩溃进程；系统保存已经产生的安全内容，任务进入失败或相应停止状态，并返回脱敏结构化错误。

### 工具过滤与安全边界

- **F24：** 子 Agent 的有效工具集合必须按收窄规则计算：父上下文可用集合与角色白名单（未声明则不额外收窄）取交集，再移除角色黑名单和全局禁止工具；仅当任务实际处于后台承载时，再移除后台白名单之外的工具。任何过滤层都不能重新开放已被前层移除的工具。
- **F25：** 被过滤的工具不得出现在发给模型的工具定义中；模型伪造调用被过滤或未知工具时，系统不得执行，必须返回可恢复的结构化拒绝/未知工具结果。
- **F26：** 后台白名单默认只包含已注册且同时标记为只读、无副作用和适合并发后台运行的工具（首版至少包括现有的 `Read`、`Glob`、`Grep`）；配置可收窄或扩展该集合，但扩展仍受角色过滤、权限规则和硬安全约束限制。
- **F27：** 文件范围、命令安全、Plan Mode、Hook 和现有权限系统继续在每次工具执行前生效；子 Agent 不能通过角色正文、模型选择或工具过滤绕过这些约束。
- **F28：** 子 Agent 的执行深度、任务数量和后台队列必须受系统限制；任何递归、超限或非法任务都要以可恢复结果/诊断呈现，而不是无限创建任务。

### 后台任务管理与结果回流

- **F29：** 后台任务管理器为每个委派分配稳定任务标识，并追踪至少以下状态：排队、运行中、等待确认、已完成、失败、已取消、超时/达到上限。每个任务还必须保留角色、类型、来源、开始/结束时间、停止原因、最终摘要、错误摘要和 Token 用量。
- **F30：** 进入后台必须支持三条路径：调用时显式指定、前台首轮运行超过默认 10 秒后自动转入（阈值可配置）、用户在 TUI 中手动切换。切换只改变承载方式，不重启或复制任务；Fork 式始终直接进入后台。
- **F31：** 任务进入后台后与父请求的取消信号解耦；任务只响应自身取消和应用关闭。父请求结束、切换会话或继续输入不得自动终止已入后台任务。
- **F32：** 后台并发默认最多 4 个，排队默认最多 32 个，两个上限均可配置。超过任一上限时立即返回可恢复的队列满错误，不阻塞主 Agent。
- **F33：** 子 Agent 的文本增量、思考增量、工具状态、确认请求、循环进度、Token 用量、完成、失败、取消和停止原因必须通过带任务标识的机器可读事件流发布；TUI 可以实时展示这些事件。
- **F34：** 子 Agent 完成后，系统异步向主 Agent 发布结构化 `subagent_result` 通知，至少包含任务标识、状态、最终摘要、停止原因和用量。若主 Agent 当前仍在运行，结果在下一次安全的模型回灌边界提供；若主 Agent 已结束，结果进入待消费通知，不能隐式启动新的模型回合。
- **F35：** 用户显式发起的任务必须在 TUI 任务列表和任务详情中可见；完成结果可查看并以简短摘要呈现，详细子 Agent 工具轨迹默认不并入主会话。
- **F36：** 主 Agent 消费子任务结果时，结构化结果可以进入主会话的工具结果/通知历史；只有脱敏后的摘要和必要元数据可进入用户可见消息，临时消息、思考和完整工具轨迹不得污染主会话。
- **F37：** TUI 必须支持按任务查看状态和结果、取消未完成任务、处理等待确认，并在后台任务完成或失败时向当前主对话显示异步通知；过期或不存在的任务操作返回明确错误。
- **F38：** 任务结果、事件、诊断和通知必须沿用现有敏感信息脱敏、输出限长和结构化错误边界；不得暴露 API key、完整凭据或未截断的工具输出。

## 非功能需求

- **N1（稳定契约）：** Agent 委派工具的名称、参数结构和事件类型在定义式与 Fork 式之间保持稳定；新增角色或插件不得改变主工具的公开契约。
- **N2（确定性加载）：** 在相同来源内容、配置和插件注册顺序下，最终角色快照、覆盖结果、诊断顺序、模型/工具过滤结果和任务状态转换必须确定，不得依赖文件系统遍历或无序集合顺序。
- **N3（原子快照）：** 角色加载、校验和发布必须以不可部分观察的快照完成；加载失败或刷新失败时，现有运行任务继续使用已绑定快照，不能看到半更新角色。
- **N4（有界资源）：** 角色文件、frontmatter、正文、任务输入、事件载荷、工具结果、任务摘要、后台队列和任务保留数量都必须有明确上限；超过上限时拒绝或截断并标记，不得无界增长。
- **N5（运行时隔离）：** 并行子 Agent 之间以及子 Agent 与主 Agent 之间不得共享可变消息、授权临时状态、确认通道、读缓存或用量计数；隔离边界应可通过并发测试观察。
- **N6（基础设施复用安全）：** 共享 LLM 客户端、Hook 引擎和文件系统访问必须支持并发使用，并保持各请求的模型、权限、取消、脱敏和事件身份不串线。
- **N7（Fork 缓存效益）：** Fork 的父上下文快照必须保留稳定、可缓存的系统指令与工具定义前缀；首次 Provider 请求应复用父请求的缓存边界并启用提示缓存（Provider 不支持缓存时不影响正确性），角色附加指令只能位于该稳定前缀之后。
- **N8（安全收窄）：** 任何角色、插件、模型输出、后台配置或用户界面操作都不能扩大应用原始工具集合、突破全局禁止、路径沙箱、Plan Mode、Hook 或权限硬约束。
- **N9（权限 fail-closed）：** 权限规则损坏、角色权限模式非法、工具过滤状态不完整、任务身份无法验证或安全链发生异常时，危险操作必须拒绝；拒绝结果须可恢复且不导致进程崩溃。
- **N10（取消与收尾）：** 任务取消、Provider 错误和应用关闭必须停止后续工作，避免启动新工具或模型请求；所有后台执行单元、队列项和事件通道都必须在有界时间内收尾，不得泄漏或死锁。
- **N11（事件顺序）：** 单个任务的事件必须按可观测的序列号和任务标识排序；并发工具结果仍须按模型调用顺序回流，前后台切换不得丢失或重复终端事件。
- **N12（事件解耦）：** 事件载荷必须与 Provider 和 TUI 实现无关；不连接真实 TUI 时仍可通过事件消费者验证完整生命周期，TUI 不需要了解底层 Provider 协议。
- **N13（结果一致性）：** 任务管理器中的最终状态、主 Agent 收到的结构化结果和 TUI 展示的终态必须来自同一份不可变完成快照，状态、停止原因、摘要和用量不得互相矛盾。
- **N14（敏感信息保护）：** 角色路径、frontmatter、任务参数、模型响应、工具输出、权限提示、事件、诊断和任务结果在跨模块或持久化前都必须经过统一脱敏与限长；任何 API key、Token、密码或完整敏感命令不得泄露。
- **N15（交互兼容）：** 没有子 Agent 委派时，现有普通对话、Agent Loop、Skill、权限确认、Plan Mode、会话保存、Memory、MCP 和 TUI 行为保持等价；已有工具不能因引入后台管理器而改变确认语义。
- **N16（模型选择隔离）：** 角色的模型别名只影响该子 Agent 任务，不修改全局 Provider 配置、不影响父会话、其他任务或后续默认请求；并行任务可使用不同模型。
- **N17（后台可用性）：** 短任务前台交互不应因任务登记或状态查询明显阻塞；显式后台、自动切换和手动切换应保持同一任务身份与事件连续性。
- **N18（可诊断性）：** 每个拒绝、配置错误、队列满、超时、取消、Provider 错误和结果回流失败都必须提供机器可读原因及脱敏的人类可读摘要；用户能区分正常完成、等待确认、达到上限、取消、失败和队列拒绝。
- **N19（并发上限）：** 默认并发 4、队列 32 的限制必须在竞态和高负载下仍成立；配置值必须在启动时校验，非法或溢出值 fail-closed。
- **N20（验证性）：** 角色解析、覆盖、两种上下文构造、工具过滤、权限隔离、后台转移、取消、结果回流和 TUI 状态都必须可在不连接真实 Provider、不启动完整 TUI 的情况下测试，并提供至少一个真实 TUI 端到端场景。
- **N21（进程生命周期）：** 本轮不要求后台任务跨会话或跨进程持久化；应用重启或关闭后未完成任务不得伪造成功结果，已完成的用户可见摘要仍遵循主会话既有保存规则。
- **N22（实现范围）：** 本轮不引入 Worktree 文件隔离、多 Agent 团队编排、跨会话后台任务恢复、网络工具、全新权限规则格式或独立的 Provider 协议。

## 不做的事

- 不实现 Worktree、容器或其他项目文件级隔离；子 Agent 只隔离运行时状态，仍使用现有项目文件边界。
- 不实现多 Agent 团队编排、任务 DAG、角色之间自动协商或共享黑板。
- 不实现后台任务跨会话、跨进程持久化、重启恢复或远程任务接管。
- 不实现新的 Provider 协议、账号、Base URL 或任意模型 ID；角色模型只使用既定别名映射。
- 不实现网络、浏览器、MCP 之外的新工具，也不允许角色或插件动态注册底层工具。
- 不实现角色市场、远程下载、安装、版本依赖、签名验证或图形化角色编辑器。
- 不实现插件目录扫描；本轮只提供插件角色来源的注册接口。
- 不实现角色自定义权限规则、免确认策略、永久授权或对现有硬安全约束的覆盖。
- 不让子 Agent 递归启动孙 Agent；不提供无限深度或由模型自由创建任务树的能力。
- 不把父会话的临时授权、确认结果、读缓存或用量计数复制给子 Agent。
- 不把子 Agent 的完整思考、临时消息、工具轨迹或未脱敏输出写入主会话；主会话只接收结构化结果和必要摘要。
- 不因子任务结果自动开启新的主 Agent 模型回合；结果只在安全回灌边界提供给主 Agent。
- 不实现后台文件监听器；角色来源变化不产生无界后台刷新。
- 不改变现有普通对话、Skill、权限、Plan Mode、Hook、Memory、MCP 和会话存储的既有协议与安全边界。
- 不把“进入后台”解释为绕过用户确认；后台任务仍遵守现有权限链，需要确认时暂停等待 TUI 决策。

## 验收标准

### 委派入口与启动路径

- **AC1（F1–F4）：** 分别由主 Agent 工具调用和 TUI 显式入口提交一个定义式任务；两者均生成同一格式的任务记录、事件序列和终态。提交非法类型、空任务或未知角色时，观察到结构化可恢复错误，且没有子任务被创建。
- **AC2（F4、F14）：** 提交一个 Fork 任务并同时请求前台运行；观察任务直接进入后台，父会话继续可输入，且子任务只使用委派瞬间的上下文快照。
- **AC3（F5–F7）：** 加载合法角色文档后，角色目录显示名称和用途，运行请求包含完整正文；加入空名称、未知 frontmatter 字段、非法模型/权限模式、负轮次和空正文文档时，文档被判无效并产生脱敏诊断。
- **AC4（F8–F10）：** 在项目、用户、内置、插件四个来源放置同名和不同名角色，观察最终目录按项目 > 用户 > 内置 > 插件覆盖；同层有效重名使初始加载失败，运行中刷新失败时旧快照和正在运行的任务保持不变。
- **AC5（F9）：** 让高优先级同名文档损坏、低优先级版本有效；观察低优先级版本继续生效且出现脱敏诊断。
- **AC6（F10–F12）：** 角色快照发布后，新增/修改角色不会使一次正在运行的任务中途切换正文；指定无法映射的模型别名或放宽父权限模式时，委派准备失败且全局配置不被修改。

### 上下文与状态隔离

- **AC7（F13）：** 定义式任务的 Provider 请求包含标准系统/安全指令、项目指令、角色正文和任务内容，但不包含父会话消息。
- **AC8（F14、N7）：** Fork 任务的首次 Provider 请求包含委派时父消息、系统环境和已过滤工具；捕获请求可观察到稳定缓存前缀/缓存策略，父会话之后新增消息不会出现在子请求中。
- **AC9（F15–F16）：** 并行运行两个子任务并分别修改消息、确认状态、读缓存和用量；观察任一任务的变化不会出现在另一任务或主会话，且共享 Provider/Hook/文件系统仍可正常服务两者。
- **AC10（F17）：** 父会话已有临时授权时，子任务对同一危险工具仍按自身规则重新确认；子任务的本次/本会话授权不会放行父会话后续调用。
- **AC11（F18）：** 让子 Agent 请求再次委派；观察得到可恢复的递归拒绝结果，没有新增任务、队列项或后台运行实例。

### 执行、权限与停止

- **AC12（F19–F20）：** 使用会请求多个工具的模型 fixture，观察子 Agent 连续执行直到无工具调用并进入正常完成；达到全局/角色较小轮次上限时不再请求模型，并显示达到上限原因。
- **AC13（F21）：** 让子 Agent 请求需要确认的危险工具；观察任务进入等待确认，TUI 显示任务标识和参数摘要；选择允许后继续，选择拒绝后生成结构化拒绝结果且不执行工具。
- **AC14（F22–F23）：** 在模型流错误、工具不可恢复错误、任务取消和应用关闭场景中，观察任务停止且不启动新模型/工具；已完成内容保留，错误信息脱敏，进程不崩溃。
- **AC15（F24–F27）：** 为父上下文、角色白/黑名单、全局禁止和后台白名单设置互相冲突的工具集合；观察最终集合严格按收窄规则计算，过滤工具不出现在 Provider 定义中，伪造调用也被拒绝，现有路径/Plan/Hook/权限限制继续生效。
- **AC16（F26）：** 在默认后台配置下提交只包含 `Write`、`Edit` 或 `Bash` 等非默认后台工具的任务；观察这些工具不会出现在 Provider 工具定义中，伪造调用在执行前被拒绝。显式扩展后台白名单后，再观察危险工具仍进入现有确认流程，不能因后台模式自动放行。
- **AC17（F28、N19）：** 连续提交超过并发 4 或排队 32 的任务；观察超限请求立即收到队列满错误，实际运行数和排队数不超过配置值。

### 后台生命周期、事件与回流

- **AC18（F29）：** 创建定义式和 Fork 式任务，任务详情能显示唯一标识、角色、类型、来源、时间、状态、停止原因和 Token 用量；状态按排队→运行/等待确认→完成/失败/取消等合法路径变化。
- **AC19（F30）：** 分别使用显式后台、首轮超过 10 秒的自动后台和 TUI 手动切后台；观察任务标识、已产生事件和执行进度连续，任务不重启、不重复执行工具。
- **AC20（F31）：** 任务转后台后取消父请求并继续发送普通消息；观察子任务仍运行并最终报告结果，只有任务自身取消或应用关闭才停止它。
- **AC21（F32）：** 修改并发/队列配置后重复 AC17；观察新上限在下一次任务调度中生效，非法配置在启动时 fail-closed。
- **AC22（F33、N11–N13）：** 消费不带 TUI 的机器事件流；观察每个事件带任务标识和顺序信息，包含文本/思考、工具、确认、进度、用量和终态事件；前后台切换无丢失、重复或矛盾终态。
- **AC23（F34）：** 让后台子任务完成，观察主 Agent 收到结构化 `subagent_result`，字段包含任务标识、状态、最终摘要、停止原因和用量；主 Agent 正在运行时只在下一安全回灌边界看到结果。
- **AC24（F34、N21）：** 让主 Agent 在子任务完成前结束，观察结果进入待消费通知；下一次主请求可读取该结果，但系统不会自动额外发起模型回合。
- **AC25（F35–F37）：** 在 TUI 中查看任务列表/详情、处理确认、手动切后台、取消任务和查看成功/失败结果；不存在或过期任务操作显示明确错误，当前对话仍可继续。
- **AC26（F36）：** 主 Agent 消费结果后，主会话只新增结构化工具结果或脱敏摘要；子 Agent 的思考、临时消息和完整工具轨迹不出现在主会话。
- **AC27（F38、N14）：** 在角色正文、参数、工具输出、错误和任务摘要中注入模拟密钥、Token、密码和超长内容；用户可见目录、事件、诊断、任务详情和会话记录中不出现原始秘密，超长内容被截断并标记。

### 兼容性与端到端

- **AC28（N15）：** 在不创建任何子 Agent 的情况下运行普通对话、Skill、Plan Mode、权限确认、Memory、MCP 和会话恢复；既有行为与基线一致。
- **AC29（N16）：** 并行提交不同模型别名的任务；观察模型选择只影响对应任务，父会话、其他任务和后续默认请求不变。
- **AC30（N20）：** 在无真实 Provider、无完整 TUI 的测试环境中完成角色解析、覆盖、两种上下文构造、工具过滤、权限隔离、后台转移、取消、队列和结果回流验证；再运行至少一个真实 TUI 端到端场景。
- **AC31（N21–N22）：** 应用重启/关闭时未完成任务不会被标记为成功或跨进程恢复；验证不产生 Worktree、团队编排或跨会话后台记录。
