# XAgent Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 实现完整性
- [ ] XAgent 可以在终端启动并进入交互界面（验证：运行 `go run ./cmd/xagent`，观察到 TUI 界面）
- [ ] 对话界面提供可输入区域（验证：启动后输入文本，输入内容可见）
- [ ] 非空输入可以提交（验证：输入问题并提交，界面出现本轮 user 消息）
- [ ] 空输入不会发送模型请求（验证：提交空输入，界面仍可输入且没有新增模型响应）
- [ ] 模型回复以流式方式逐步渲染（验证：提交问题后观察 assistant 内容逐步出现）
- [ ] 流式渲染完成后保留完整对话内容（验证：响应结束后能看到完整 user 和 assistant 消息）
- [ ] 同一会话内支持多轮上下文（验证：第二轮提问依赖第一轮内容，模型能基于前文回答）
- [ ] 模型回复完成后会追加到当前会话历史（验证：响应结束后会话文件包含本轮 user 和 assistant 消息）
- [ ] 退出后重新启动可以看到历史会话（验证：完成一轮对话后退出并重启，历史列表出现该会话）
- [ ] 可以选择历史会话继续对话（验证：从历史列表选择会话，继续输入并获得回复）
- [ ] 继续历史会话时携带历史上下文（验证：重启后继续追问前文内容，模型能基于历史回答）
- [ ] YAML 配置可以决定当前 Provider（验证：切换 `protocol` 后观察请求走对应后端）
- [ ] YAML 配置可以决定模型名称（验证：修改 `model` 后请求使用新模型）
- [ ] YAML 配置可以决定 API 地址（验证：使用 mock server 的 `base_url`，请求命中 mock server）
- [ ] YAML 配置可以提供 api_key（验证：请求头包含配置中的认证信息）
- [ ] Anthropic Provider 支持流式响应（验证：使用 Anthropic 配置提交问题，观察流式回复）
- [ ] OpenAI Provider 支持流式响应（验证：使用 OpenAI 配置提交问题，观察流式回复）
- [ ] Claude extended thinking 请求能力可开启（验证：开启 thinking 后，请求体包含 thinking 参数）
- [ ] thinking 配置为显示时界面区分展示 thinking 和最终回复（验证：开启 show 后观察 thinking 区块与 assistant 区块分开）
- [ ] thinking 配置为隐藏时界面只展示最终回复（验证：关闭 show 后观察界面不展示 thinking 内容）
- [ ] 每次模型响应完成后显示耗时（验证：响应结束后状态栏或消息区显示本轮耗时）
- [ ] 用户可以通过明确操作退出（验证：按退出键或退出命令，程序结束）
- [ ] 退出前保存当前会话历史（验证：退出后检查会话文件存在且内容完整）
- [ ] 首版没有 tool use、文件操作、代码编辑或命令执行入口（验证：界面和配置中不存在这些入口）

## 集成
- [ ] 命令入口正确加载配置并创建 Provider（验证：不同 `protocol` 配置启动后状态显示对应 Provider）
- [ ] 命令入口正确初始化会话存储（验证：首次启动后数据目录可创建，退出后会话文件可写入）
- [ ] 提示词/资源层被流式编排使用（验证：mock Provider 接收到的请求包含系统提示词）
- [ ] TUI 应用层不直接依赖 Anthropic/OpenAI 协议细节（验证：切换 Provider 时 TUI 行为不变）
- [ ] Provider 层把底层 SSE 转换为统一事件（验证：mock Anthropic/OpenAI SSE 均转换为 text/done 事件）
- [ ] 流式编排层能把 Provider 事件转成 TUI 应用事件（验证：fake Provider 输出 delta/done 后，TUI 收到增量和完成事件）
- [ ] 会话层只把 user 和 assistant 消息作为普通上下文发送（验证：含 thinking 的历史会话中，OpenAI 请求不包含 thinking 角色消息）
- [ ] 状态栏不会泄露 api_key（验证：启动和请求过程中界面上不出现配置中的 api_key）
- [ ] 错误事件能从 Provider 传递到 TUI（验证：mock server 返回错误，界面显示可理解错误）
- [ ] 错误后用户仍能继续操作（验证：触发一次错误后继续输入，界面不崩溃）

## 编译与测试
- [ ] 项目依赖可整理（验证：运行 `go mod tidy` 成功）
- [ ] 全部包可测试（验证：运行 `go test ./...` 成功）
- [ ] 命令行程序可编译（验证：运行 `go build ./cmd/xagent` 成功）
- [ ] 配置模块测试通过（验证：运行 `go test ./internal/config` 成功）
- [ ] 会话模块测试通过（验证：运行 `go test ./internal/conversation` 成功）
- [ ] Provider 模块测试通过（验证：运行 `go test ./internal/provider` 成功）
- [ ] 流式编排模块测试通过（验证：运行 `go test ./internal/orchestrator` 成功）
- [ ] TUI 框架模块测试通过（验证：运行 `go test ./internal/tui` 成功）
- [ ] TUI 应用模块测试通过（验证：运行 `go test ./internal/app` 成功）

## 错误反馈
- [ ] 配置文件缺失时显示可理解错误（验证：不提供配置启动，观察错误信息）
- [ ] protocol 无效时显示可理解错误（验证：配置未知 protocol，启动或提交前显示错误）
- [ ] model 缺失时显示可理解错误（验证：删除 model 字段，观察错误信息）
- [ ] base_url 缺失时显示可理解错误（验证：删除 base_url 字段，观察错误信息）
- [ ] api_key 缺失时显示可理解错误（验证：删除 api_key 字段，观察错误信息）
- [ ] API 认证失败时显示可理解错误（验证：使用无效 api_key 提交请求，观察错误反馈）
- [ ] 模型请求失败时显示可理解错误（验证：使用不可达 base_url 提交请求，观察错误反馈）
- [ ] SSE 流式响应中断时显示可理解错误（验证：mock server 提前断开流，观察错误反馈）
- [ ] 错误后可以退出（验证：触发错误后执行退出操作，程序正常结束）
- [ ] 错误后可以继续输入或重试（验证：触发错误后再次提交，程序继续处理）

## 端到端场景
- [ ] 场景 1：首次启动 → 新建会话 → 输入问题 → 观察流式回复 → 显示耗时 → 退出（验证：全过程无崩溃，输出符合预期）
- [ ] 场景 2：完成一轮对话 → 退出 → 重启 → 选择历史会话 → 继续追问前文 → 模型基于历史回答（验证：跨启动历史恢复和上下文生效）
- [ ] 场景 3：Anthropic 配置开启 thinking show → 输入问题 → thinking 与最终回复分区显示（验证：thinking 可见且与最终回复区分）
- [ ] 场景 4：Anthropic 配置关闭 thinking show → 输入问题 → 只显示最终回复（验证：thinking 不出现在界面）
- [ ] 场景 5：切换 OpenAI 配置 → 输入问题 → 观察流式回复 → 确认没有 Claude thinking 展示（验证：OpenAI 后端可用且行为一致）
- [ ] 场景 6：提交空输入 → 不发请求 → 继续提交正常问题（验证：空输入不会破坏后续操作）
- [ ] 场景 7：配置错误或 API 错误 → 看到错误反馈 → 修正或重试 → 程序继续可用（验证：错误恢复路径可用）
