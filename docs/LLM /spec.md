# XAgent Spec

## 背景
XAgent 是一个终端 AI 编程助手的第一阶段实现。本阶段聚焦“纯对话能力”：用户在终端启动 XAgent 后进入交互式界面，输入自然语言问题，系统调用配置的大模型后端，并把模型回复以流式方式逐步显示出来。

当前项目从零开始，尚未包含可运行的命令行程序、TUI、配置加载、模型 Provider 抽象或会话历史能力。本阶段需要建立这些基础能力，为后续加入 tool use、文件操作、代码编辑等 Coding Agent 功能打底。

## 目标
- 提供一个可在终端启动的 XAgent 交互式对话界面。
- 支持用户连续输入问题，并看到模型回复以流式方式逐步输出。
- 支持多轮对话，模型能够基于同一会话中的历史消息回答。
- 支持跨启动保存和恢复会话，用户可以查看并继续历史会话。
- 支持通过 YAML 配置文件切换 Anthropic Claude 和 OpenAI 两类模型后端。
- 支持使用 SSE 方式消费模型流式响应，而不是等待完整响应后一次性显示。
- 支持 Claude extended thinking，并允许用户通过配置控制 thinking 内容是否在界面中显示。
- 提供统一的模型 Provider 抽象，使后续可以加入新的模型后端。
- 明确排除 tool use、文件操作、代码编辑、自动执行命令等 Agent 行为，本阶段只做对话。

## 功能需求
- F1: 用户可以在终端启动 XAgent，并进入一个可持续交互的对话界面。
- F2: 对话界面需要提供清晰的输入区域，用户可以输入自然语言问题。
- F3: 用户可以通过明确的提交操作发送当前输入内容。
- F4: 用户提交空输入时，系统不应发送模型请求，并应保持在可继续输入的状态。
- F5: 系统将用户提交的问题发送给当前配置的大模型后端。
- F6: 系统必须以流式方式接收模型响应。
- F7: 系统必须以流式方式渲染模型回复，用户能够看到回复内容逐步出现，而不是等待完整回复结束后一次性显示。
- F8: 流式渲染过程中，界面应保持可读性，不应破坏已有对话内容的显示结构。
- F9: 系统支持同一会话内的多轮对话。
- F10: 每次发送新请求时，系统会把当前会话中必要的历史消息作为上下文发送给模型，使模型能够基于之前的对话回答。
- F11: 模型回复完成后，系统会把本轮用户输入和模型回复追加到当前会话历史中。
- F12: 系统支持跨启动保存会话历史，用户退出后再次启动 XAgent 时可以查看历史会话。
- F13: 用户可以从历史会话列表中选择一个会话并继续对话。
- F14: 继续历史会话时，后续请求应携带该历史会话中的上下文。
- F15: 系统通过 YAML 配置文件管理大模型供应商信息，至少包含 protocol、model、base_url、api_key 四个核心字段。
- F16: protocol 字段决定使用 Anthropic Claude 协议还是 OpenAI 协议。
- F17: model 字段决定请求的大模型名称。
- F18: base_url 字段决定 API 请求地址。
- F19: api_key 字段直接提供认证密钥。
- F20: 系统支持 Anthropic Claude 后端的流式对话响应。
- F21: 系统支持 OpenAI 后端的流式对话响应。
- F22: 系统支持 Claude extended thinking 请求能力。
- F23: 用户可以通过配置控制 Claude thinking 内容是否在界面中显示。
- F24: 当 thinking 内容配置为显示时，界面应能将 thinking 内容与最终回复区分展示。
- F25: 系统提供统一的模型 Provider 抽象，不同后端对上层对话流程呈现一致的流式输出行为。
- F26: 系统需要记录每次模型响应的耗时。
- F27: 模型回复完成后，界面需要展示本轮响应耗时。
- F28: 当配置缺失、配置无效、API 请求失败、认证失败、模型返回错误或流式响应中断时，系统需要在界面中给出可理解的错误反馈。
- F29: 发生错误后，系统应允许用户继续输入、重试或退出，而不是直接崩溃。
- F30: 用户可以通过明确的退出操作退出 XAgent。
- F31: 退出前，系统需要保存当前会话历史。

## 非功能需求
- N1: XAgent 使用 Go 开发。
- N2: XAgent 应作为命令行程序运行，不依赖图形界面。
- N3: TUI 在常见终端环境中应保持可读、可输入、可退出。
- N4: 模型响应必须通过 SSE 或等价的服务端事件流机制逐步消费，不能只使用非流式请求。
- N5: Provider 抽象应避免把 Anthropic Claude 或 OpenAI 的协议细节泄漏到上层对话流程。
- N6: 会话历史应保存在本地文件中，程序重启后仍可读取。
- N7: 本地保存的会话历史应使用稳定、可读、可迁移的格式。
- N8: YAML 配置文件加载失败或字段无效时，应在发起模型请求前给出错误反馈。
- N9: api_key 按用户要求允许以明文形式出现在 YAML 配置文件中。
- N10: 系统不应在正常界面输出中泄露 api_key。
- N11: 流式输出期间，界面不应因为单个响应较长而失去基本可操作性。
- N12: 错误信息应面向用户可理解，避免只展示底层异常或堆栈。
- N13: 首版实现范围应聚焦纯对话，不包含 tool use、文件读写、代码编辑或命令执行能力。

## 不做的事
- 不实现 tool use。
- 不让模型调用外部工具。
- 不实现文件读取、文件写入、文件搜索或代码编辑能力。
- 不实现自动执行 shell 命令。
- 不实现项目索引、代码库理解或代码跳转能力。
- 不实现 Git 操作、PR 操作或 Issue 操作。
- 不实现插件系统或第三方扩展机制。
- 不实现多 Provider 同时请求、自动 fallback 或模型路由。
- 不实现用户账号、远程同步或云端会话存储。
- 不实现加密保存 api_key。
- 不实现复杂的上下文压缩、摘要记忆或长期知识库；首版只保存并复用会话消息历史。
- 不实现非终端图形界面。

## 验收标准
- AC1: 在终端运行 XAgent 后，用户能看到交互式对话界面，并能输入内容。
- AC2: 用户提交一条非空问题后，系统会向当前配置的模型后端发起请求。
- AC3: 用户提交空输入时，系统不会发起模型请求，并仍允许继续输入。
- AC4: 模型回复会在终端中逐步出现，可以观察到流式渲染过程。
- AC5: 流式渲染完成后，界面中保留完整的用户问题和模型回复。
- AC6: 连续提出相关问题时，后续模型请求会携带前文上下文，模型能够基于之前对话回答。
- AC7: 模型回复完成后，本轮用户输入和模型回复会被追加到当前会话历史。
- AC8: 退出并重新启动 XAgent 后，用户可以看到历史会话列表。
- AC9: 用户选择历史会话后，可以继续该会话。
- AC10: 继续历史会话后，新请求会携带该历史会话的上下文。
- AC11: YAML 配置包含 protocol、model、base_url、api_key 时，系统能读取这些字段并选择对应后端。
- AC12: protocol 配置为 Anthropic Claude 时，系统使用 Claude 协议发起流式请求。
- AC13: protocol 配置为 OpenAI 时，系统使用 OpenAI 协议发起流式请求。
- AC14: Claude extended thinking 配置开启时，请求会包含 thinking 能力相关参数。
- AC15: thinking 内容配置为显示时，界面能把 thinking 内容与最终回复区分展示。
- AC16: thinking 内容配置为隐藏时，界面只展示最终回复，不展示 thinking 内容。
- AC17: 配置缺失或字段无效时，系统在发起模型请求前显示可理解的错误信息。
- AC18: API 认证失败、请求失败或流式响应中断时，系统显示可理解的错误反馈。
- AC19: 发生错误后，用户仍可以继续输入、重试或退出。
- AC20: 每次模型回复完成后，界面显示本轮响应耗时。
- AC21: 用户执行退出操作后，程序正常退出。
- AC22: 退出前当前会话历史会保存到本地。
- AC23: Provider 抽象允许上层对话流程不区分 Anthropic Claude 和 OpenAI 的流式输出处理方式。
- AC24: 本阶段不提供 tool use、文件操作、代码编辑或命令执行入口。
