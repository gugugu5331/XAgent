# XAgent 可用性与可靠性路线图 Spec

## 背景

XAgent 已具备终端 TUI、Agent Loop、工具调用、权限确认、MCP、上下文压缩、会话恢复、长期记忆等核心能力。近期通过多角度实际使用案例审查发现，系统在真实用户场景中仍存在若干高影响问题：首次启动和配置闭环不完整、请求可能长时间无响应、错误诊断不可见、权限风险提示不足、长任务参数硬编码、会话损坏恢复体验不完整、TUI 缺少帮助和可操作错误详情。

本路线图以“让用户能启动、能理解、能恢复、能安全授权、能完成长任务”为目标，按优先级分阶段修复 P0/P1/P2 问题。文档覆盖全量方向，但允许后续 plan/task 将实现拆成多个里程碑。

## 目标

- 提供可靠的首次启动与配置体验，让用户在缺配置、缺 API key、provider 错误时知道下一步怎么修。
- 防止 provider/network 长时间挂起导致 TUI 无限等待，并提供用户可见的取消与超时行为。
- 让配置中的显式关闭生效，用户能临时关闭出错的 instructions、context、memory 子系统。
- 将关键 diagnostics 暴露给用户，避免 MCP、sessionctx、JSONL、memory、context 错误静默。
- 改善工具和权限相关 TUI 体验，让用户看得懂风险、错误原因和可恢复动作。
- 让长任务的迭代轮数、工具超时、输出上限可配置，并在达到限制时给出继续路径。
- 提升会话恢复、长期记忆、项目指令兼容和帮助系统的整体可用性。

## 功能需求

- F1: 首次启动和配置错误必须给出可执行修复建议，包括配置文件缺失、必填 LLM 字段缺失、API key 缺失、模型或协议错误。
- F2: LLM API key 和相关敏感配置必须支持从环境变量展开，并在所有错误、诊断、TUI、会话记录中保持脱敏。
- F3: 用户显式配置关闭 instructions、context、memory 等子系统时，系统必须尊重该配置，不得被默认值覆盖。
- F4: Provider 请求必须有可配置超时，并允许用户在 TUI 中取消当前请求；取消后会话应保持可继续使用。
- F5: TUI 必须提供可发现的帮助入口，说明 slash 命令、快捷键、权限模式、记忆/压缩/MCP/诊断管理命令。
- F6: 未知 slash command 必须作为本地命令错误提示，而不是静默发送给模型。
- F7: sessionctx、instructions、memory、context、MCP 配置和启动过程产生的 diagnostics 必须能在 TUI 中看到，并提供查看详情的入口。
- F8: MCP 配置被禁用、环境变量缺失、初始化失败、HTTP 非成功响应、stdio stderr/protocol 错误必须提供可操作诊断。
- F9: 工具失败时，TUI 和模型上下文必须能看到足够的错误信息，包括错误码、退出码、stdout/stderr 摘要、截断提示和恢复建议。
- F10: Bash 权限确认必须明确提示 Bash 不是文件系统沙箱，只是从项目目录启动；高风险或永久授权必须清楚展示风险和撤销方式。
- F11: 权限确认界面必须展示工具名、目标命令/路径、风险、权限模式、授权范围、永久规则落点或撤销入口。
- F12: Agent Loop 最大轮数、未知工具阈值、工具执行超时、工具输出上限必须可配置，并在达到限制时提示用户如何继续或调整。
- F13: 长工具输出和截断结果必须能被用户追溯到完整内容或外置路径，避免错误上下文丢失。
- F14: JSONL 会话列表必须能展示损坏但可恢复的会话；恢复后继续保存不得被旧坏行再次阻断。
- F15: 项目指令加载必须兼容常见项目指令文件名，至少能处理当前默认文件和 Claude Code 常用文件；发现未加载但存在的候选文件时应提示。
- F16: TUI 输入和消息区域应支持复杂任务基本需求，包括长输入、多行粘贴、工具错误详情查看和自适应布局。
- F17: 会话列表和恢复提示应提供更有用的上下文，包括最近摘要、上次停止原因、恢复诊断或保存位置。
- F18: `/plan` 与 `/do` 的使用路径应更明确；至少在帮助中说明模式语义，后续可支持结构化计划引用。
- F19: 系统必须提供面向用户的诊断/状态查询入口，例如 diagnostics、MCP 状态、memory 状态、permissions 状态。
- F20: 所有新增用户可见错误和诊断必须使用一致的分类、严重级别、脱敏策略和“下一步建议”格式。
- F21: 系统必须定义敏感数据流分级，区分用户可见、模型可见、可持久化、可进入长期记忆的数据，并为每一级设置默认禁止项。
- F22: 工具 stdout/stderr、provider/MCP 响应体、诊断详情和 JSONL 恢复信息必须默认只生成脱敏限长摘要；完整原始内容不得默认进入模型上下文、JSONL、长期记忆或仓库目录。
- F23: 超大工具输出如需追溯完整内容，必须通过本地私有 artifact 机制或显式用户操作提供；artifact 不得默认暴露给模型，不得位于仓库工作区，必须具备私有权限和清理策略。

## 非功能需求

- N1: 安全优先。任何错误详情、诊断、日志、TUI 展示、会话记录、记忆内容都不得泄露 API key、token、Authorization header、password、secret 等敏感信息。
- N2: 可恢复优先。配置、provider、MCP、会话恢复、上下文压缩失败不应让整个应用进入不可继续状态，除非缺少启动必需配置。
- N3: 向后兼容。现有 config.yaml 在未使用新字段时应保持可运行；新增配置必须有合理默认值。
- N4: 渐进实现。全量路线图可以拆成多个里程碑，每个里程碑必须独立可测试、可验收。
- N5: 用户可理解。面向用户的错误必须避免只暴露底层异常，应同时包含简短原因和建议动作。
- N6: 端到端可验证。每个里程碑完成后必须能通过单元测试、全量测试和 tmux 真实交互验证。
- N7: 不引入远程依赖。诊断、帮助、状态展示应在本地完成，不依赖外部服务。
- N8: 不降低现有权限边界。任何体验优化不得绕过现有权限确认、路径保护、MCP 安全校验和脱敏规则。
- N9: Diagnostics 默认仅本地用户可见，不得作为模型消息保存，不得进入长期记忆索引，不得保存 raw error、raw body、raw stderr 或坏 JSONL 原文。
- N10: 模型可见内容必须采用最小必要原则。工具失败、HTTP 错误、MCP 错误只能向模型提供脱敏、限长、分类后的摘要。
- N11: 所有完整输出 artifact 必须保存在用户私有数据目录，目录权限 0700、文件权限 0600，并明确不在仓库工作区内。
- N12: 所有端到端验收和 handoff 证据不得包含真实 API key、Authorization、password、token、secret、cookie 或私钥内容。

## 不做的事

- 不实现真正的操作系统级 Bash 沙箱；本路线图只要求风险提示、配置、权限和可观测性改进。
- 不实现完整插件市场或 MCP 图形化管理界面。
- 不实现云端同步、团队共享记忆或远程会话存储。
- 不重写整个 TUI 框架；只在现有 TUI 上逐步增强帮助、输入、状态、详情展示。
- 不要求一次提交完成所有 P0/P1/P2；后续 plan/task 可拆分里程碑执行。
- 不把所有错误都变成阻塞错误；非致命 diagnostics 应可见但不应干扰正常对话。
- 不引入精确 tokenizer 或复杂任务调度系统，除非后续独立 spec 批准。

## 验收标准

- AC1: 在缺少配置文件、缺少 LLM 必填字段、缺少 API key 的情况下启动，用户能看到具体修复命令或配置建议。
- AC2: 使用环境变量配置 API key 时，请求能成功；环境变量缺失时错误信息脱敏且指出缺失变量。
- AC3: 配置 `instructions.enabled: false`、`context.enabled: false` 或 `memory.enabled: false` 后，对应子系统不再运行或注入上下文。
- AC4: Provider 请求超过配置超时时，TUI 显示超时错误和建议；用户取消请求后可继续输入下一条消息。
- AC5: 输入 `/help` 能看到本地命令、快捷键、权限模式和常用状态命令；输入未知 slash command 会得到本地错误提示。
- AC6: 构造 instructions include 越界、memory index 损坏、context 摘要失败等场景时，TUI 能显示或查询到对应 diagnostics。
- AC7: MCP 环境变量缺失、stdio server 启动失败、HTTP 401/403 时，用户能看到 server 名称、错误分类、脱敏详情和建议动作。
- AC8: Bash 命令失败时，TUI 中能看到退出码、stderr/stdout 摘要；模型后续轮次也能基于失败详情自我修正。
- AC9: Bash 权限确认明确展示“非沙箱”风险；永久授权显示落点或撤销入口。
- AC10: 调整 Agent Loop 最大轮数、工具超时、输出上限配置后，运行行为随配置变化；达到限制时提示继续方式。
- AC11: 超大工具输出被截断或外置时，用户能看到截断提示和追溯完整内容的方式。
- AC12: 包含坏行的 JSONL 会话仍出现在列表中，可恢复；恢复后继续保存成功。
- AC13: 项目存在 `CLAUDE.md` 但默认指令文件不存在时，系统能加载或提示兼容路径。
- AC14: TUI 能处理多行粘贴或长输入，不会破坏布局；消息区宽度随终端变化合理展示。
- AC15: 会话列表能展示比首条消息更有用的信息，至少包括最近摘要或上次停止原因中的一种。
- AC16: `/plan` 和 `/do` 在帮助中有清晰说明；误用时给出本地提示。
- AC17: 新增 diagnostics、错误详情、状态输出均通过脱敏测试，不泄露 token、api_key、Authorization、password、secret、cookie、私钥或运行期展开出的 secret。
- AC18: 每个实现里程碑均通过 `go test ./...`，并用 tmux 完成至少一个真实端到端场景。
- AC19: Bash stdout/stderr、MCP body、provider body 中包含固定敏感样本时，TUI、模型上下文、JSONL、diagnostics、memory index 均不出现原文。
- AC20: 诊断详情不会被作为 conversation message 保存，也不会进入长期记忆；JSONL 恢复诊断只包含行号、错误类型和可恢复状态，不包含坏行原文。
- AC21: 超大工具输出被截断时，TUI 显示截断摘要和完整内容追溯方式；完整内容 artifact 位于私有目录、权限正确、默认不暴露给模型。
- AC22: `/diagnostics`、`/mcp status`、`/permissions status` 输出均标明是本地诊断/状态，并通过统一脱敏矩阵测试。
