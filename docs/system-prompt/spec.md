# System Prompt Spec

## 背景

XAgent 已具备工具系统和 Agent Loop，但当前全局系统提示仍是单段静态文本，且内容与现有能力不匹配。随着工具调用、规划模式、执行模式、安全边界和输出规范增多，系统提示需要从“短字符串”升级为可组合、可缓存、可按轮次注入的结构化提示体系。

本章目标是让稳定指令尽量复用缓存，动态上下文通过系统级补充消息注入，减少 token 成本和响应延迟，同时提高模型对工具约定、代码编辑约定、安全边界和输出风格的遵守率。

缓存验证优先面向 Anthropic。OpenAI 保持统一 usage 和请求抽象，但不要求本章证明真实 prompt cache 命中。

## 目标

- 将全局指令拆成按职责和优先级排列的模块，形成稳定、可扩展的系统提示结构。
- 区分稳定内容与动态内容，让稳定指令和工具描述进入可缓存通道，让环境信息、会话模式和临时指令进入动态注入通道。
- 通过系统提示和工具描述双重强化关键规则，提升模型对工具使用约定的遵守率。
- 支持带特殊标签的系统级补充消息，运行中注入环境、模式和动态指令，但不让模型把它当作用户输入回复。
- 支持请求内 Agent Loop 轮次注入策略，控制首轮完整、间隔轮次重复、其余轮次精简。
- 解析并展示 Anthropic 缓存创建、缓存读取和普通输入输出 token，用于验证缓存策略是否生效。
- 准备可复现的人工对比清单，用典型任务观察结构化提示是否改善工具使用和输出稳定性。

## 功能需求

- F1: 系统必须提供结构化全局提示，由固定模块按优先级拼装：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出。
- F2: 每个固定模块必须包含明确的核心句义：身份模块声明 XAgent 是终端 AI 编程助手；系统约束模块声明遵守安全边界和系统优先级；任务模式模块声明默认、Plan、Do 的职责差异；动作执行模块声明先观察再行动、遇到阻塞要说明；工具使用模块声明优先专用工具、编辑前先读取、路径限制在项目内、危险工具谨慎；语气风格模块声明中文、简洁、直接；文本输出模块声明结果优先、必要时给验证证据。
- F3: 系统必须支持可选稳定模块追加在固定模块之后。本章只保留可选模块插槽和拼装机制，不加载真实项目指令文件、Skill 内容或长期记忆内容。
- F4: 系统必须用空行分隔模块，并保持稳定模块输出顺序确定，确保相同配置下生成的稳定提示文本字节级一致。
- F5: Provider 请求模型必须能区分稳定系统块、动态系统补充、普通对话历史、工具描述和缓存策略。实现不得只把所有内容拼成单个会变化的系统提示字符串。
- F6: 稳定模块和工具描述必须进入 provider 的可缓存请求区域；环境信息、运行模式、Agent Loop 轮次提示和对话历史不得进入稳定缓存块。
- F7: Anthropic provider 必须在稳定提示与工具描述的稳定边界设置缓存控制，使动态补充位于缓存边界之后。不支持真实缓存的 provider 必须退化为普通请求且行为不失败。
- F8: 系统必须提供系统级补充消息格式，用特殊标签包裹动态指令，明确其为系统补充而非用户输入，模型不应直接回应这些标签内容。
- F9: 动态系统补充消息必须在每次 provider 请求前由运行时状态生成，不作为普通 user/assistant/tool 历史保存，不显示为用户消息；如需调试，只能记录非用户可见的结构化元数据或事件。
- F10: 动态补充消息不得把用户可控内容提升为系统指令。环境信息和路径等动态内容必须以结构化或转义后的形式注入，且动态补充优先级低于稳定系统约束。
- F11: 系统必须支持按运行模式注入动态指令：默认模式、Plan Mode、Do Mode 都能得到对应约束。当前模式以单次用户请求为生命周期；同一请求内的所有 Agent Loop provider 调用都必须保持该模式约束。
- F12: Plan Mode 的只读约束必须在动态指令、工具暴露或工具执行路径两侧同时生效。即使模型请求 Write、Edit、Bash，也必须被系统拒绝或不暴露。
- F13: 系统必须支持请求内轮次化注入策略：同一用户请求的第 1 次 provider 调用注入完整模式说明；之后按固定 Agent Loop iteration 间隔重复关键约束；其余 iteration 注入精简提示。
- F14: 工具描述和全局工具模块必须重复关键规则，至少覆盖“优先使用专用工具”“编辑前必须先读”“危险工具谨慎执行”“路径限制在项目内”。
- F15: 工具定义和工具 schema 输出必须稳定，至少保证同一工具集合在连续请求中的顺序确定，避免无意义 cache miss。
- F16: Anthropic provider 必须解析缓存相关 usage 字段，包括缓存创建输入 token、缓存读取输入 token、普通输入 token 和输出 token；OpenAI provider 保留普通 usage 兼容，缓存字段可为空或为零。
- F17: UI 或事件流必须能展示请求级累计 usage，包括普通输入/输出 token、缓存创建 token、缓存读取 token，让开发者判断是否产生缓存命中。
- F18: 系统必须提供可复现的人工对比清单，至少覆盖读文件、编辑前读取、Plan Mode 只读、危险命令确认、最终回复简洁性和缓存 usage 观察。

## 非功能需求

- N1: 稳定提示构建必须是确定性的，避免 map 无序遍历、时间戳、随机值或动态环境进入缓存块。
- N2: 动态注入内容必须短小可控，避免每一轮重复大量不变文本导致 token 浪费。
- N3: 新结构必须兼容现有 Agent Loop、工具调用、Plan Mode 和对话历史保存行为。
- N4: 不支持缓存字段的 provider 不应因此失败，应继续完成普通流式对话和工具调用。
- N5: 提示内容必须避免引入越权、绕过安全边界或鼓励执行危险操作的表述。
- N6: 异常路径必须保持可调试性：provider 流出错、用户取消、未知工具过多和达到迭代上限时，已产生的用户消息、助手文本、工具调用和工具结果仍应按现有 Agent Loop 规则保存。

## 不做的事

- 不加载项目级指令文件。
- 不实现自动记忆系统。
- 不接入真实 MCP 服务。
- 不做自动化评估框架。
- 不实现跨会话 prompt cache 管理后台或成本统计报表。
- 不把 Skill、长期记忆或自定义指令做成完整产品能力；本章只保留可选稳定模块插槽。
- 不改变现有权限系统边界；Plan Mode 的只读限制仍必须由工具注册或执行路径强制兜底。

## 验收标准

- AC1: 给定默认配置时，系统能生成包含七个固定模块且顺序稳定的全局提示文本。
- AC2: 固定模块包含本 spec 要求的核心句义，尤其是工具使用、编辑前读取、路径限制、安全边界和中文简洁输出。
- AC3: 可选稳定模块为空时不会产生多余占位符；提供可选内容时会按规定位置追加且顺序稳定。
- AC4: 环境信息和运行模式说明不会进入稳定提示块，而是通过系统级补充消息注入。
- AC5: 动态系统补充消息不会写入普通会话历史，不会显示为用户消息，且不会破坏 provider 对 user/assistant/tool 消息顺序的要求。
- AC6: `/plan` 请求的同一 Agent Loop 内所有 provider 调用都包含 Plan Mode 约束；首轮完整，间隔轮次重复关键约束，其余轮次精简。
- AC7: Plan Mode 下请求中不暴露或不执行 Write、Edit、Bash；即使模型请求这些工具，也会得到只读限制结果。
- AC8: 工具描述和全局工具模块都包含关键工具规则，至少覆盖“优先专用工具”和“编辑前先读”。
- AC9: Anthropic 请求中稳定提示和工具描述位于缓存边界内，动态补充位于缓存边界后；连续相同稳定内容请求不会因动态环境或轮次文本变化改变稳定缓存块。
- AC10: Anthropic 流式响应中的缓存创建和缓存读取 token 能被解析、累计并展示。
- AC11: OpenAI provider 在不支持缓存命中字段时仍可正常请求、流式输出和展示普通 usage。
- AC12: 同一工具集合连续构造请求时，工具定义顺序和稳定提示文本保持一致。
- AC13: 运行人工对比清单时，能记录输入、期望工具序列、实际工具序列、最终输出和 usage/cache 指标。
- AC14: 全量测试通过，现有 Agent Loop 和工具系统 smoke 场景不回退。
