# Skill System Spec

## 背景

XAgent 已具备统一斜杠命令、持续模式、动态系统上下文、工具注册与多轮 Agent Loop，但可复用 AI 操作仍需用户反复输入完整提示词。现有 `/review` 等固定提示无法携带独立元信息、限制工具、按需加载资源，也无法表达共享对话与独立执行两种生命周期。

本功能引入 Skill：以 Markdown 能力包描述可复用 SOP，通过三级来源发现和覆盖。启动时只向 Agent 暴露 Skill 名称与一句说明，只有被用户调用或 Agent 选中后才加载完整指令，从而控制上下文体积并提高工具选择准确率。

## 目标

- 用 YAML frontmatter 与 Markdown 正文定义可复用 AI 操作。
- 支持项目、用户、内置三级来源及确定性的同名覆盖。
- 实现“轻量目录 → 按需加载完整 SOP”的两阶段加载。
- 将活动 Skill 持续置于显眼的系统环境上下文中，支持多个共享 Skill 同时激活。
- 支持共享主对话和隔离临时对话两种执行模式。
- 使用工具白名单收窄可见工具，同时保留系统级 Skill 加载能力。
- 将有效 Skill 自动注册为可发现的斜杠短命令，并在交互边界支持热更新。
- 提供 `commit`、`review`、`test` 三个可直接使用和参考的内置样板。
- 保持现有权限确认、会话恢复、流式事件、Plan 只读约束和敏感信息脱敏边界。

## 功能需求

- F1：每个 Skill 必须由 YAML frontmatter 和非空 Markdown 正文组成。frontmatter 包含唯一名称、一句话说明、可选工具白名单、执行模式、独立模式历史轮次数和可选模型；正文作为完整 SOP 指令。
- F2：Skill 名称必须使用大小写不敏感的规范名称，能够安全映射为斜杠命令；说明不能为空；执行模式只能是“共享”或“独立”；历史轮次数必须是非负整数。
- F3：系统必须同时支持两种能力包形态：
  - 单文件 Skill：Skill 根目录下的 Markdown 文件。
  - 目录型 Skill：目录入口固定为 `SKILL.md`，同目录可包含模板、示例、脚本和参考文档。
- F4：目录型 Skill 激活时只加载入口正文，并向 Agent 提供经过规范化的包根路径。辅助文件不得自动内联，必须通过 Skill 白名单允许的现有工具按需访问。
- F5：系统必须从以下三级来源发现 Skill，优先级从高到低为：
  1. 项目 `.xagent/skills/`
  2. 用户 `~/.config/xagent/skills/`
  3. 程序内置 Skill
  不同层级同名时，高优先级的有效定义覆盖低优先级定义。
- F6：单个文件无法读取、frontmatter 无效或正文为空时，必须跳过该文件、记录脱敏诊断，并继续加载其他 Skill。无效的高优先级文件不应遮蔽低优先级的有效同名 Skill。
- F7：同一层级出现多个有效同名 Skill 时属于配置冲突。首次启动必须失败并指出冲突来源；热更新遇到该冲突时拒绝整个候选快照并继续使用上一个有效快照。
- F8：首次启动必须在完整工具注册完成后验证所有最终生效 Skill 的工具白名单。任何白名单工具不存在时立即启动失败。热更新遇到不存在的工具时拒绝新快照、保留旧快照并显示脱敏诊断。
- F9：系统必须实现两阶段加载：
  - 目录阶段：只把最终生效 Skill 的规范名称和一句说明注入 Agent 上下文。
  - 激活阶段：用户调用或 Agent 选择后，才加载完整 SOP、执行元信息和包根路径。
- F10：系统必须提供一个内置系统工具供 Agent 按名称加载 Skill。该工具始终可见，不受任何 Skill 白名单限制，但不能被 Skill 定义覆盖或替换。
- F11：完整 SOP 中只支持保留占位符 `{{args}}`。系统用斜杠命令或加载工具收到的完整参数文本进行一次性字面替换，不递归执行模板，也不解析命名参数。
- F12：共享模式 Skill 被调用后必须立即执行，并在当前主会话保持激活。其完整 SOP 必须在每一轮环境上下文重建时持续置于显眼位置，直到活动状态被清除。
- F13：多个共享 Skill 可以同时激活。活动指令必须按规范名称稳定排序，避免激活顺序造成 Prompt 漂移。重复激活同一 Skill 时，用最新有效版本和最新参数替换该 Skill 的活动快照。
- F14：用户通过 `/name args` 调用共享 Skill 时，主历史保存原始短命令及参数作为用户消息；完整 SOP 只存在于系统环境上下文，不复制到用户消息历史。
- F15：独立模式 Skill 被调用后必须立即创建临时执行上下文，只激活目标 Skill，不继承主会话中已激活的共享 Skill。临时上下文包含标准系统环境，以及配置要求的最近 N 个完整用户轮次。
- F16：独立模式中的一个完整用户轮次包括该用户消息、对应助手回复以及其间关联的工具调用和工具结果，不得按裸消息数量从中间截断。
- F17：独立模式必须复用现有权限规则、用户确认、取消、超时和实时工具进度事件。其详细消息与工具轨迹不得并入主历史；最终回复必须按可回流摘要格式输出，并直接作为主会话助手结果保存，不增加第二次摘要模型调用。
- F18：可选模型对两种模式都生效。共享 Skill 激活期间的后续 Agent Loop 使用指定模型；独立 Skill 仅在临时执行期间使用指定模型；没有模型覆盖时使用应用默认模型。
- F19：多个活动共享 Skill 指定的非空模型必须一致。激活一个模型冲突的 Skill 时，本次激活失败，既有活动状态保持不变。清除活动状态后恢复应用默认模型。
- F20：多个活动 Skill 的工具白名单必须取交集；未声明或空白名单表示该 Skill 不额外限制工具。最终工具集合还必须与 Plan 只读限制求交，且不能扩大应用原始工具集合。
- F21：工具白名单只控制向模型暴露和允许调用的工具，不绕过现有权限系统。系统级 Skill 加载工具始终额外保留。模型调用未暴露或未允许的工具时，必须按现有未知/拒绝工具路径处理。
- F22：每个最终生效 Skill 必须自动注册同名斜杠短命令，并进入 `/help` 与 Tab 补全；帮助和候选菜单需标注其 Skill 身份及共享/独立模式。
- F23：现有基础设施命令及别名为保留名称。硬编码 `/review` 必须迁移为内置 review Skill；其他与保留命令冲突的 Skill 仍可通过系统加载工具使用，但不注册短命令，并产生诊断。
- F24：系统必须在下一次用户输入、命令补全或新 Agent 请求前检查 Skill 变化并原子刷新有效目录与动态命令。已激活 Skill 保持加载时快照；只有重新激活后才采用新版本。被删除的活动 Skill 也保持到清除或重新激活失败为止。
- F25：`/clear` 必须继续保留会话历史和 Agent 上下文消息，但额外清除全部活动 Skill。新建会话、切换会话和应用重启也必须清除活动 Skill；活动状态不持久化。
- F26：首版不提供逐个卸载命令。加载失败、模型冲突或热更新失败不得部分修改当前活动状态。
- F27：系统必须内置三个样板：
  - `commit`：共享模式，允许 `Read`、`Glob`、`Grep`、`Bash`，使用默认模型。
  - `review`：独立模式，携带最近 1 个完整用户轮次，允许 `Read`、`Glob`、`Grep`、`Bash`，使用默认模型。
  - `test`：独立模式，携带最近 1 个完整用户轮次，允许 `Read`、`Glob`、`Grep`、`Bash`，使用默认模型。
  三者必须提供实际可执行的 SOP，而不只是格式示例。
- F28：所有 Skill 路径、解析错误、热更新诊断、工具错误和回流摘要必须沿用现有敏感信息脱敏边界。

## 非功能需求

- N1：Skill 发现、覆盖、帮助顺序、目录注入顺序、活动指令顺序和动态命令顺序必须确定。相同文件集合和输入必须产生相同结果，不依赖文件系统遍历或映射迭代顺序。
- N2：两阶段加载必须真实控制模型上下文体积。未激活 Skill 的正文、模板、示例和参考资料不得进入 Provider 请求；目录阶段只能出现名称和一句说明。
- N3：活动 Skill 指令必须在同一请求的首轮、工具结果后的请求以及所有后续 Agent Loop 轮次中保持一致，不得在重建 Prompt 时丢失。
- N4：Skill 目录、动态命令和校验结果必须作为一个不可分割的有效快照发布。刷新成功时整体替换；刷新失败时整体保留旧快照，不允许部分更新。
- N5：刷新和激活操作必须串行化或具备等价的一致性保护。并发输入、补全和 Agent 请求不得看到半更新目录，也不得产生重复或顺序不确定的活动状态。
- N6：热更新采用交互边界检查，不要求后台文件监听器。未发生文件变化时应使用轻量缓存判断，不得在每次补全中重复解析全部正文。
- N7：Skill 发现、解析、帮助、补全和热更新检查不得访问网络、调用模型或消耗对话 Token。
- N8：Skill 文件和包路径必须规范化并限制在所属 Skill 根目录内。目录入口、辅助资源和符号链接不得借由路径穿越暴露任意文件。
- N9：活动目录型 Skill 的包根可以作为额外只读根提供给 `Read`、`Glob`、`Grep` 等读取类工具；`Write`、`Edit` 等写入能力仍受项目根限制。Skill 包路径不得自动获得写权限。
- N10：工具白名单只能减少模型可见和可调用的工具，不能扩大基础注册中心、Plan Mode 或权限系统授予的能力，也不能把危险工具变成免确认工具。
- N11：系统级 Skill 加载工具虽然不受白名单隐藏，但仍必须校验 Skill 名称、参数大小、执行深度和当前快照，不得成为任意文件读取、任意 Prompt 注入或权限绕过通道。
- N12：可选模型覆盖必须是请求或执行上下文级别，不得修改全局 Provider 配置，也不得影响其他会话、后续默认请求或并行的独立执行。
- N13：独立模式必须使用消息副本，不修改主会话原有消息。除原始 Skill 命令、实时界面事件和最终摘要外，不得向主历史写入临时消息、工具轨迹或思考内容。
- N14：独立临时会话不单独持久化、不进入会话列表，也不直接更新长期记忆；只有回流到主对话的最终摘要可以按主会话既有规则参与后续上下文与记忆处理。
- N15：共享模式必须保持现有普通输入、流式回复、工具批处理、权限确认、上下文压缩和会话保存行为。没有活动 Skill 时，Provider 请求应与引入本功能前等价。
- N16：Skill 激活、模型冲突、白名单过滤、独立执行、热更新和清除操作必须可在不启动真实 TUI、不连接真实 Provider 的情况下测试。
- N17：解析和诊断必须有合理的文件数量、单文件大小、正文大小和参数大小边界。超过边界的单个 Skill 按无效文件跳过并产生脱敏诊断，不得造成无界内存或 Prompt 增长。
- N18：项目 Skill 和用户 Skill 属于本地指令来源，但其正文及辅助文件仍不得覆盖系统级安全约束、Plan Mode、权限策略、脱敏规则或系统加载工具。
- N19：独立模式必须遵守现有请求取消和超时语义。用户取消后不得继续后台调用 Provider 或执行工具，也不得写入不完整摘要。
- N20：系统必须防止无限递归启动独立 Skill。首版在独立执行内部再次请求独立 Skill 时应明确拒绝；加载共享 Skill 时只影响当前临时上下文，不影响主会话。
- N21：所有新增行为必须通过格式检查、静态检查、全项目自动化测试以及真实 TUI 端到端场景，不得引入命令系统、会话恢复、Memory、MCP、权限或 Agent Loop 回归。

## 不做的事

- 不建设 Skill 市场、远程目录、下载、发布、评分或自动更新服务。
- 不实现 Skill 版本号解析、依赖解析、锁文件、升级策略或版本回滚。
- 不从 URL、Git 仓库、MCP Server 或模型输出动态安装 Skill。
- 不允许 Skill 在运行时注册新的底层工具；白名单只能引用启动时已经存在的工具。
- 不允许 Skill 声明独立权限规则、免确认策略或绕过现有权限系统。
- 不实现后台文件系统监听器；热更新只在用户输入、补全和请求边界检查。
- 不支持命名参数、条件、循环、表达式或可执行模板；首版仅支持 `{{args}}`。
- 不支持 Skill 命令别名；规范 Skill 名称就是唯一短命令名称。
- 不提供逐个卸载 Skill 的命令或工具动作；首版通过 `/clear`、新建或切换会话清除活动状态。
- 不持久化活动 Skill、模型覆盖或有效白名单；应用重启后全部恢复默认状态。
- 不让独立 Skill 自动继承主会话活动 Skill。
- 不允许独立 Skill 递归启动另一个独立 Skill。
- 不把目录型 Skill 的所有资源自动内联进 Prompt，也不让系统加载工具读取任意辅助文件。
- 不把独立临时会话保存到会话列表，不提供打开、恢复、重命名或继续临时会话的能力。
- 不为单个 Skill 创建新的 Provider 协议、Base URL、API Key 或账号；可选模型只能覆盖当前 Provider 下的模型名称。
- 不让热更新改写已激活快照；重新激活前，当前执行继续使用原版本。
- 不允许 Skill 覆盖现有基础设施命令、系统加载工具、安全提示、Plan Mode 或脱敏规则。
- 不在本阶段提供图形化 Skill 编辑器、脚手架生成器、签名验证或信任管理界面。

## 验收标准

- AC1（F1–F4）：给定合法单文件 Skill 和目录型 Skill，系统能读取全部 frontmatter、非空 SOP 和规范包根；辅助资源不自动进入模型上下文。
- AC2（F2）：空名称、空说明、非法名称、未知执行模式、负数历史轮次或空正文均被判为无效 Skill，并给出可定位且脱敏的诊断。
- AC3（F5）：内置、用户、项目存在同名 Skill 时，最终目录只出现项目版本；移除项目版本后使用用户版本，再移除后恢复内置版本。
- AC4（F6）：一个损坏或超限文件不会阻止其他有效 Skill 加载；损坏的高优先级文件不会遮蔽低优先级有效版本。
- AC5（F7）：同一层级存在两个有效同名 Skill 时，首次启动失败并指出两个来源；运行中制造同样冲突时，目录和命令继续使用旧快照。
- AC6（F8）：最终生效 Skill 引用不存在工具时，首次启动在接受输入前失败；热更新加入不存在工具时拒绝更新且应用继续运行。
- AC7（F9）：未激活任何 Skill 时，捕获的 Provider 请求只包含所有有效 Skill 的名称和一句说明，不包含任何 SOP 正文、示例、模板或参考资料。
- AC8（F10、F21）：Agent 能根据目录调用系统级 Skill 加载工具；即使当前 Skill 白名单为空或极窄，该工具仍然可见且可以加载合法 Skill。
- AC9（F11）：正文中的所有 `{{args}}` 被完整参数文本做一次字面替换；参数中的模板符号不被二次解释，未定义命名占位符不产生额外解析行为。
- AC10（F12、F13）：共享 Skill 激活后，首轮请求、工具结果后的请求和多轮 Agent Loop 都包含相同活动 SOP；多个共享 Skill 按规范名称稳定排列，重复激活会原子替换该 Skill 快照。
- AC11（F14）：执行共享 Skill 短命令后，主历史保存原始 `/name args`，不保存展开 SOP；执行结果和后续普通对话留在主会话。
- AC12（F15、F16）：独立 Skill 只收到标准系统环境、目标 SOP 和最近 N 个完整用户轮次；不会继承主会话活动 Skill，也不会截断某轮内部的工具调用链。
- AC13（F17）：独立 Skill 的危险工具仍触发正常权限确认，流式文本和工具状态可实时观察；完成后主历史只增加原始命令和最终摘要，不包含临时工具轨迹。
- AC14（F17）：独立执行只使用其最终回复回流，不发生额外摘要模型调用；取消、超时或失败时不写入伪造的成功摘要。
- AC15（F18、F19）：共享 Skill 指定模型后，后续各轮均使用该模型；独立 Skill 只在临时执行中使用指定模型；激活不同模型的第二个共享 Skill 会失败且原活动状态不变。
- AC16（F20、F21）：两个活动白名单取交集，并继续受 Plan 只读限制；未声明白名单不额外收窄；被过滤工具既不出现在 Provider 工具定义中，也不能通过伪造调用绕过执行检查。
- AC17（F22、F23）：有效 Skill 出现在 `/help` 和 Tab 补全中，并标注执行模式；硬编码 `/review` 已由内置 review Skill 接管；与其他保留命令冲突的 Skill 仍能被加载工具使用，但没有短命令。
- AC18（F24）：新增、修改、删除 Skill 后，下一次输入或补全能看到新的目录与命令；已激活 Skill 继续使用旧正文，重新激活后才切换到新正文。
- AC19（F24）：热更新中的解析错误只跳过对应文件；同层重名或无效工具白名单导致整个候选快照被拒绝，旧目录、旧命令和旧活动状态保持一致。
- AC20（F25、F26）：`/clear` 清除全部活动 Skill，但消息历史数量和 Agent 上下文消息不变；新建、切换会话和重启也恢复无活动 Skill 及默认模型。失败的激活不会留下部分状态。
- AC21（F27）：内置 `commit`、`review`、`test` 均可被发现、补全和执行；模式、历史轮次数、模型和工具白名单与规格一致，SOP 能驱动实际提交、审查和测试工作流。
- AC22（F4、F28）：目录 Skill 可以通过允许的读取类工具访问自身包内资源；不能越出包根读取，也不能借 Skill 资源根让写入工具修改项目外文件。
- AC23（F28）：在 Skill 路径、frontmatter、参数、解析错误、工具结果和独立摘要中注入模拟 API Key、Token 和密码后，目录、诊断、状态栏和消息输出均不出现原始敏感值。
- AC24（F10、F15、F26）：独立执行内部尝试再次启动独立 Skill 时得到明确可恢复错误；加载共享 Skill 只影响临时上下文，不污染主会话活动状态。
- AC25（F1–F28）：没有 Skill 或没有活动 Skill 时，普通输入、命令、会话保存、Memory、MCP、权限确认、上下文压缩和 Plan Mode 的既有自动化测试保持通过。
- AC26（F1–F28）：运行格式检查、静态检查、全项目测试和当前源码构建均成功。
- AC27（端到端）：在真实 TUI 中依次验证目录轻量注入、`/review` 独立运行、`/commit` 共享激活、工具过滤、模型冲突、热更新、`/clear` 清除活动状态和无效白名单启动失败，所有可见行为与本规格一致。
