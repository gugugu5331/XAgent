# Context Management Spec

## 目标

给 XAgent 增加上下文管理能力，使长时间对话和 Agent Loop 不会因为工具结果、历史消息累积而耗尽上下文窗口。

核心策略分两层：

1. 轻量预防压缩：优先处理 token 大头，也就是工具结果。
2. 重量兜底摘要：当整体上下文接近模型窗口时，用 LLM 生成结构化摘要，替换较早历史。

## 原则

- 用户原始消息尽量保留原文，不主动改写成摘要。
- 工具结果可以外置，但会话里必须保留预览、路径、大小和重新读取提示。
- 摘要只是线索，不是事实来源；需要代码和工具输出细节时必须重新读取文件。
- 压缩在每次 API 请求前执行：先轻量，再判断是否需要重量摘要。
- 自动压缩保留 13K token 安全余量；手动压缩保留 3K token 安全余量。
- 本阶段使用近似 token 估算，不引入精确 tokenizer。

## 轻量预防压缩

触发条件：

- 单个工具结果超过阈值。
- 同一会话内未外置工具结果合计超过阈值。

行为：

- 将完整结构化工具结果写入 `storage.data_dir/context_blobs/<conversation_id>/`。
- 会话消息中保留：
  - 预览内容
  - 外置文件路径
  - 字节数
  - “如需完整细节，请重新读取该文件，不要根据预览或摘要脑补”的提示
- 已外置消息再次压缩时必须幂等跳过。

## 重量兜底摘要

触发条件：

- 自动：估算上下文超过 `model_window_tokens - auto_margin_tokens`。
- 手动：用户输入 `/compact`，并且存在可摘要的早期消息。

保留策略：

- 从尾部保留近期原文，目标约 `recent_keep_tokens`。
- 至少保留 `recent_keep_messages` 条消息。
- 不拆散 `tool_call` / `tool_result` 配对。

摘要格式固定为：

1. 当前目标
2. 已完成事项
3. 关键决策与约束
4. 重要文件/符号线索
5. 工具结果与外置文件索引
6. 未完成任务/下一步
7. 风险与不能臆测的内容

摘要请求约束：

- 使用 provider 发送一次无工具请求。
- `Tools` 必须为空。
- Prompt 明确禁止工具调用。
- Prompt 要求模型先做分析草稿，再输出正式摘要；只有正式摘要进入 conversation，草稿丢弃。

## 边界消息

每次重量摘要成功后，插入边界消息：

- 提醒模型上下文已压缩。
- 摘要只提供线索，不是完整事实来源。
- 如需代码、文件或工具结果细节，必须重新读取相关文件或外置结果。
- 禁止根据摘要脑补代码细节。

## 失败与熔断

- 摘要失败不会阻断普通对话。
- 连续失败达到 `summary_failure_limit` 后，自动摘要熔断。
- 熔断后自动请求只做轻量外置，不再反复重试摘要。
- 手动 `/compact` 在熔断后返回明确错误。

## 非目标

- 不实现精确 tokenizer。
- 不实现机器学习摘要策略。
- 不引入完整 slash command 框架。
- 不把摘要当作可替代源码/工具结果的事实来源。
